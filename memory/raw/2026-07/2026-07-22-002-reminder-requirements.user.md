~~~~text
在“功能需求、非功能需求、用户使用流程、配置与数据存储、待讨论事项”章节中，如果讨论过初步想法，可以在章节末尾适当补充。需求文档首先承载最客观、需要实现的需求，其次才是实现思路，便于之后依据文档进行有架构的实现。

以下是已确认的需求，应整理到需求文档中。

项目用途：

- Windows 桌面提醒程序，用于定时提醒用户休息眼睛、喝水以及其他自定义事件。
- 帮助长时间使用电脑的用户建立规律的休息和饮水习惯。

轻量化要求：

- 程序需要尽可能轻量，因为预计会长期在后台运行。
- 尽可能降低后台内存和 CPU 占用。
- 空闲时不应频繁轮询。
- 不应因提醒功能明显影响电脑性能。
- 不应持续显示占用桌面的主窗口。
- 长时间运行需保持稳定。
- 避免为简单功能引入过于庞大的依赖或运行环境。
- “轻量”是项目的重要目标，但具体内存、CPU 和安装包大小指标尚未确定，需要后续讨论。

提醒方式：

- 优先使用 Windows 自带的系统通知机制。
- 通知方式符合 Windows 使用习惯，不应显得突兀。
- 尽量避免自行实现遮挡屏幕的弹窗，尽量利用 Windows 通知中心。
- “喝水提醒”和“休息眼睛提醒”应是两种可以区分的提醒。
- 具体采用哪一种 Windows 通知接口，等架构讨论后确定。

后台运行：

- 程序能够长期在后台运行，并按设定时间触发提醒。
- 用户关闭可见窗口后程序继续运行；只有通过系统托盘图标右键点击“退出”才能退出程序。
- 需要系统托盘图标，并考虑用户如何暂停、恢复或退出程序。
- 需要考虑电脑睡眠、休眠、唤醒后的提醒处理。
- 用户锁屏期间不发送提醒，因为用户没有在使用电脑。
- 程序异常退出后的处理方式：“也不用怎么处理吧，就按照原计划即可。比如说……”；此处表达未完成，待确认。
- 支持开机自动启动，并允许用户自行设置是否启用。
- 支持静默启动。
- “静默启动”设置旁最好有小问号图标，鼠标移上去显示说明：“程序启动时以后台模式运行，不显示程序面板”。

提醒时间与事件控制：

- 喝水提醒、休息眼睛提醒以及用户添加的每个自定义事件都使用相互独立的计时。
- 每个事件可单独设置提醒时间间隔。
- 事件既可从现在开始按固定间隔提醒，也可设定未来某一时刻，从该时刻起按固定间隔提醒。
- 可单独启用或禁用某一种提醒。
- 可暂停单个事件提醒。
- 可暂停全部事件计时：正在计时的事件暂停；尚未开始计时的事件如果在暂停期间到达起始时间，也不提醒；暂停结束后按原来设定的固定时间间隔正常提醒。
- 可重启单个事件提醒和全部事件提醒；只有当前已经在计时且采用固定时间间隔的事件才能重启。
- 支持延迟本次提醒。此功能可能使全屏游戏退出全屏；“这个没得做”，用户只有将游戏设为窗口化才能不退出游戏并打开其他内容。程序只需提醒用户这是正常现象。
- 可为提醒事项设置截止时间，也可设为无截止时间。
- 用户可设置电脑休眠时是继续计时还是重新计时；仅对固定时间间隔事件生效。
- 用户可设置电脑息屏时是继续计时还是重新计时；仅对固定时间间隔事件生效。
- 用户事件界面同步显示每个提醒事件的倒计时。

版本与联网：

- 主页显示版本号。
- 如果有新版本，在版本号旁显示一个 `new`，无需其他提示，只做轻量提醒。
- 版本检查需要联网，但不持续联网；隔很长一段时间联网同步一次，检查是否有新版本。
- 联网失败不提醒用户，保持程序干净。

界面与交互：

- 软件不需要新手引导，因此设计必须简洁明了。
- 对复杂提醒逻辑，可采用事件列表：每个事件占一行；第一列为事件名称；第二列为提醒方式，例如“从现在开始固定时间间隔”或“从未来某一时刻开始固定时间间隔”。
- 第二列上方使用滑块控制第二列的选项，选定后再设置该选项对应的参数。
- 对用户功能中“多选一”的逻辑，可以使用滑块控制模块选项，再配置选定选项，使用户无需自行总结哪些功能可能冲突，并让每个事件保持简洁明了。
- 界面不能太古老，应具有简洁、简约、干净、高级的感觉，可参考 Clash Verge 的程序面板。
- 浅色主题通体采用白色，深色主题通体采用暗色。
- 主题可由用户自行设置，也可跟随系统。

需要总结上述全部内容，并理解用户所想的方向，但不要把模型自己的想法加入需求文件。模型可以先与用户讨论自己的想法，只有经用户确认后才总结到需求文档。需求文档不需要链接记忆文件，它是独立的需求文档。

当前先不讨论技术细节；模型应提出希望与用户讨论的功能想法。
~~~~

~~~~text
用户认可按“不可提醒状态 × 固定间隔事件/指定时间事件”分类推演逻辑。

### 固定时间间隔事件

- 软件未运行时，保存退出时的计时状态，包括已经暂停的事件；离线时间不计入计时，相当于全部冻结，软件启动后继续正常运行。
- 软件启动时应优先读取已有事件及其保存时间。
- 对休眠、息屏或锁屏，固定间隔事件可以设置“继续计时”“重新计时”“暂停计时”三种策略。
- 采用“继续计时”时，还可以设置在对应状态期间是否发送提醒。
- 如果选择不发送提醒，且这期间到达提醒时间，则电脑亮屏后提示一次“已跳过”。

### 指定时间事件

- 指定时间事件只在指定时间产生提醒。
- 如果提醒时间落在暂停期间或软件未运行期间，则记录为跳过，在恢复时发送“已跳过该事件”通知。
- 对休眠、息屏或锁屏，可以设置“亮屏提醒”或“不提醒”两种策略。
- 如果配置为需要提示，且对应状态期间到达提醒时间，则电脑亮屏后提示一次“已跳过”。

### 错过提醒与通知

- 同一个事件错过多次，只发送一条“已跳过”。
- 所有事件都不显示错过次数，也不需要显示下一次提醒时间。
- 不同事件的错过信息合并为一条通知，列出错过了哪些事件。
- “已跳过”通知是纯通知，不带操作按钮。
- 多个普通事件恰好在同一时间到点时，仍然分别发送多条普通提醒通知，不因计划时间相同而合并。

### 一次性、过去时间和截止时间

- 一次性事件错过后提示“已跳过”，不安排下一次提醒。
- 事件保留在列表中，但最后一列开关显示为关闭。
~~~~
