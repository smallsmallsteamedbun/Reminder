# 长期精炼记忆

## 项目记忆约定

- 本项目采用项目内 `memory/` 分层记忆系统，用于跨长对话、上下文压缩、中断和跨会话恢复。
- 记忆层分为近原始用户消息、当前工作状态、会话摘要、历史索引、长期精炼知识和有效决策；各层不得相互替代。
- `memory/` 内生成的标题、字段、状态、说明和总结统一使用中文；路径、代码、命令、专有名词等精确信息可保留原文。
- 用户消息默认进入只追加的 `memory/raw/`；以 `[NO_MEMORY]` 开头的消息不记录正文或派生细节。
- 当前协议及完整读写规则见 `AGENTS.md` 的 “Codex Memory Protocol”。
- 来源：`memory/sessions/2026-07/2026-07-22-001-codex-memory-design.md`

## 版本控制约定

- 只有用户明确要求上传时，才能把项目推送或以其他方式同步到 GitHub 等远程仓库；本地编辑、准备提交或本地提交本身不自动授权远程上传。
- 用户执行项目还原时，可能有意连同 `memory/` 一起还原。还原后应重新读取恢复出来的当前记忆、长期记忆、决策和相关会话，并把恢复后的记忆状态视为当前记录，不擅自补回被还原掉的后续记忆。
- 首次 GitHub 存档目标为 `origin/main`，提交消息为“确认需求文档绝大多数逻辑，准备好第一次构建初步简易代码”。

## Reminder 项目定位

- Reminder 是面向 Windows 的桌面提醒程序，核心用途是提醒用户休息眼睛、喝水以及处理其他自定义提醒事件。
- 项目重视长期后台运行时的轻量、稳定、低打扰，以及简洁、现代的界面体验。
- 需求和架构将通过多轮讨论逐步确定；`docs/REQUIREMENTS.md` 是持续维护的独立需求文档，只记录已确认需求和用户已确认的初步想法。
- 已确认但不适合堆入主需求文档的提醒状态、边界和示例持续记录在 `docs/REMINDER_LOGIC_DETAILS.md`；该文件用于细化需求，不另行改变需求。
- 单条事件的界面字段、条件化表单、运行状态和全局事件控制记录在 `docs/EVENT_FORM_DESIGN.md`。
- 后续所有已确认的新需求、需求修改和需求补充都必须同步更新 `docs/REQUIREMENTS.md`，不能只保留在聊天或记忆记录中。
- 当前所有提醒采用统一事件模型；初始的“喝水”和“休息眼睛”只是默认关闭、可以删除的示例事件。
- 点击“添加事件”后立即新增一条默认事件；名称默认“新建事件”，使用第一列文本框直接编辑并允许重名。每条事件由不向用户显示的内部 `event id` 唯一识别。
- 当前提醒时间模型分为“从设置时开始的固定间隔”和“指定时间按一次性、每天、每周、每月或每年重复”两类；指定时间允许位于过去，由调度规则处理。
- Windows 通知需要直接提供“完成”“延迟”“跳过本次”；完成后从实际完成时间重新计算固定间隔。
- 通知采用 Windows 原生布局和关闭入口；按钮操作只处理提醒，不显示主面板。
- 轻量化采用事件驱动、单一最近到期计时器和仅在面板可见时刷新倒计时的原则。CPU 目标在界面显示和隐藏时都低于 1%；内存目标为界面显示时低于 160 MB、隐藏时低于 100 MB；安装包以不超过 300 MB 为可接受目标。指标允许弹性，但应尽量满足并继续降低占用。
- 桌面应用框架已先确定为 WPF。通知关闭叉号按“跳过本次”处理；通知自行消失按“延迟”处理，并使用全局延迟时长再次发送同一次提醒。程序必须区分这两种关闭原因。
- 通知自动消失时间和“延迟”时长都属于全局设置：自动消失默认 10 秒，延迟默认 5 分钟，均不再按事件分别设置。
- 开发阶段允许框架依赖构建；正式发布采用自包含 MSIX 安装包和 Windows App Installer，初始不提供便携版。
- 初期测试版本也必须结合未来功能扩建进行架构设计，代码应能作为正式实现基础继续演进，不能采用难以延续的一次性临时结构。
- 初步简易版本以简单 UI 和固定时间间隔事件的最小可运行闭环为目标：添加事件、倒计时、暂停/恢复/重启、隐藏面板后后台运行、Windows 通知及其按钮处理。首版不实现数据保存、启动恢复、完整退出、主题切换和其他完整功能，但仍需保留向完整版本扩展的结构，并验证通知接口能否区分关闭叉号与自动消失。
- UI 保留 Windows 的交互风格与高级感，不完全复刻 Windows；采用顶部页面结构、冷灰底色、低饱和靛蓝主色和自定义卡片层次，不设置宽侧边栏。`0.0.0` 只实现这一方向的单一浅色主题。
- Reminder 程序代码保持为一个 WPF 项目，不按职责拆成多个独立的 Visual Studio 项目；项目内部划分为 `UI`、`Logic`、`Windows`、`System` 四个主要模块。模块调用不采用僵硬的单向限制，但各模块必须保持自身职责；提醒业务数据由 `Logic` 修改，`Windows` 检测系统活动并通知 `Logic`，`UI` 按需读取并显示结果。
- 调度逻辑不直接操作界面或直接调用 Windows 通知；界面不直接修改后台计时器，而是把操作交给 `Logic`。不建立巨大全局变量池，各模块维护自身状态并按需取用；只有版本号等不可变固定信息作为全局共享数据。
- 用户通过托盘主动退出时必须保存所有恢复所需状态。软件未运行期间固定间隔、经过延迟调整的当前剩余时间和限时暂停倒计时全部冻结；启动时优先加载事件和保存时间。指定时间事件在暂停或离线期间到点时记为已跳过。
- 实际睡眠或休眠不再提供任何用户策略，也不在期间发送提醒；唤醒后对期间到点事件提示一次已跳过。息屏和锁屏仍可配置：固定间隔事件采用继续、重新或暂停计时，指定时间事件采用亮屏提醒或抑制后恢复提示。
- 固定间隔在不可提醒期间采用继续计时时，错过通知后仍保持原有时间节奏；“已跳过”通知不显示下一次时间，但循环调度内部仍计算未来计划。
- 同一事件错过多次只汇总一次，不显示次数和下次时间；不同错过事件合并为一条无按钮通知。普通事件同时到点时仍分别通知。
- 真正恢复需要程序运行、用户解锁、事件未单项暂停且全部暂停结束。一次性事件完成或错过后自动关闭并保留在列表。
- 事件开关与暂停属性分开保存：开启切换为关闭时复用暂停逻辑；直接从关闭拨回开启时同时恢复；修改关闭事件并保存后自动开启，但不改变暂停属性。
- 延迟操作直接把事件当前剩余时间改为所选延迟时长，不维护独立延迟状态。一次性或已无未来计划的过去事件提示已跳过后关闭，依靠时间、计划和开关避免重复，不增加“该次计划已处理”字段。
- 固定间隔暂停结束后继续暂停前的剩余时间；执行单项或全部重启时，符合条件的固定间隔事件从 `0` 开始新的完整间隔。
- 月度或年度循环遇到本周期不存在的日期时直接跳过该周期；计划时间恰好等于当前时间或真正恢复时刻时按正常到点处理。
- 版本检查只在一天中首次启动时执行一次，检查失败保持安静；用户确认更新后若更新失败，则显示软件内“更新失败”页面。版本信息来源尚未确定，发布方向倾向 GitHub。
- 托盘菜单包含打开主页、快捷全部暂停、全部恢复、版本号和退出。主题默认跟随系统，并要求浅色和深色背景下字体颜色保持清晰。
- 每条事件使用带底框、可横向滚动的双行卡片。第一行包含名称、暂停/恢复、重启、秒级只读倒计时、开关和删除；暂停或关闭的卡片显示得更淡。第二行包含事件类型动态表单及息屏、锁屏策略。
- 新建自定义事件默认名称“新建事件”、开启、不暂停、采用 45 分钟固定时间事件，终止次数默认“不终止”。指定时间频率为仅一次、每天、每周、每月、每年，切换频率时以当时的一小时之后初始化所需日期和时间字段。
- 息屏、锁屏策略是事件级属性并随事件类型变化；固定时间事件默认“暂停计时”，选择继续计时时默认“不提醒”。实际睡眠或休眠仍是固定行为，不提供事件表单选项。暂停、开关、删除适用于全部事件，重启只适用于已经开始计时的固定时间事件。
- 所有有效事件都显示精确到秒的下一次提醒倒计时；失效事件通常留空，但每次启动有 5% 概率显示“弹一万遍反方向的钟”。
- 全部暂停对所有事件生效，全部重启只影响符合条件的固定时间事件。
- Windows 原生通知不能为每条事件任意设置整体背景色或文字颜色；Windows 11 仅提供绿色 `Success`、红色 `Critical` 两种按钮语义样式，因此当前不增加“通知颜色”事件属性。原生通知时长只提供 `short`、`long`，精确的全局秒数需要在通知接口选型时验证。
- 删除截止时间设置，只使用“不终止”或 1 至 100 次的终止次数。完成或跳过本次后扣减 1，关闭叉号属于跳过并扣减；延迟和通知自动消失不扣，延迟后的同一次提醒最终只扣 1。纯信息“已跳过”汇总对其中每个不同事件分别扣减 1，同一事件在同一段不可提醒状态中错过多次仍只扣减 1。减到 0 后自动关闭并显示“不终止”。指定时间选择“仅一次”时不显示终止次数设置。
- 息屏和锁屏正式共用一套策略。指定时间事件的重启按钮置灰，频率默认“仅一次”，息屏/锁屏默认“不提醒”。第一行确定为六列。两个初始示例继续默认关闭，具体预设参数以后再讨论。
- 所有允许用户自定义输入的表单都必须在接受、保存或参与计算前检查合法性；非法格式、异常长度或过大数值不得造成溢出攻击风险、程序崩溃或错误状态。各字段的具体边界与提示方式后续逐项确定。
- 当前版本号为 `0.0.0`；第一位用于重大架构重构，第二位用于新功能上线，第三位用于当前版本内的 Bug 修复。
- 未来持久化确定采用版本化 JSON：使用 `System.Text.Json` 序列化为 UTF-8 字节，再由 Windows DPAPI 以当前用户范围整体保护；加载前检查完整性，写入时先完成临时文件再原子替换正式文件，必要时保留备份。`0.0.0` 暂不实现持久化。
- `docs/V0.0.0_IMPLEMENTATION_PLAN.md` 已完成编码前范围、目录、边界、顺序和验收标准整理；截至归档时尚未修改任何 Reminder 业务代码或 XAML。
- 正常运行期间约每 1 小时低频保存一次状态，不要求每次用户操作立即写盘；异常退出回退到最近快照并造成小幅节奏变化是可接受的。系统时间或时区变化不做额外历史校正，继续按当前时间、计划和开关判断。
