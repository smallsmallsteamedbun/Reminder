## 摘要

用户确认下一阶段采用数据持久化、启动恢复与完整退出计划，并新增“运行数据和备份都放在软件自身文件夹内、统一使用相对路径、不在 C 盘其他位置静默创建数据”的要求。本轮只研究路径和目录名称，不修改业务代码。调研确认目录式软件通常使用 `Data` 作为用户数据目录；但标准 MSIX 安装目录只读，不能直接在 exe 旁创建运行数据，因此新的目录要求与既有 MSIX 发布方向存在冲突，发布方式需要在实施前明确调整。

## 关键要点

- 建议以程序实际目录为基准，使用 `Data` 相对目录；不能依赖进程当前工作目录。
- 简单结构可以使用 `Data\state.dat`、`Data\state.bak` 和 `Data\state.tmp`，让正式状态、备份和原子写入临时文件都清楚可见。
- PortableApps.com 的目录规范使用 `Data` 保存用户设置、配置和其他原本会进入 AppData 的内容，可作为命名依据。
- 微软官方说明 MSIX 部署后的软件包文件只读，不支持应用写入安装目录；标准替代位置是 AppData，但这不满足用户“不占用 C 盘其他位置”的要求。
- 若坚持软件目录内相对 `Data`，后续发布需要改为用户可写目录中的自包含目录版，或者使用允许选择安装目录并明确配置 `Data` 写权限的传统安装方式；不能继续假定标准 MSIX 可直接满足。
- Windows DPAPI 当前用户保护仍会使状态文件绑定当前 Windows 用户和机器；目录可整体移动不代表加密状态可以跨用户或跨电脑解密。
