## 摘要

用户完成 `0.2.0` 备份后授权实施下一阶段。项目完成单项暂停、全部暂停与 Windows 状态的分层改造，接入限时全部暂停、事件级息屏/锁屏策略、睡眠固定规则、错过事件汇总和 Windows 状态监测。用户随后依据 `Win+L` 实机体验修订全局恢复语义、下拉框滚轮、主页全局按钮与通知状态，并要求解决锁屏画面变黑后通知不点亮显示器的问题。用户进一步发现关闭通知权限后重新启动仍暂时显示已就绪，因此通知服务又增加了启动主动检测。项目完成相应修正，继续保持单一最近到期计时器和按需 Windows 调用；未提交或上传。

## 关键要点

- 全部恢复和全部重启按最新规则只检查事件是否开启，并解除所有已开启固定时间事件原有的单项暂停；指定时间事件仍没有重启语义。
- 限时全部暂停使用一个全局到期时刻，不增加轮询；界面可见时沿用现有秒级刷新显示剩余时间。
- 全部暂停快捷时长增加 1 分钟，主页面全部暂停与全部恢复合并为一个切换按钮。
- 收起的下拉菜单不再用滚轮切换选项，展开列表仍能用滚轮浏览；位于事件列表中的收起下拉框把滚轮交还给列表。
- Windows 通知状态移到右下角；未就绪时使用红色，并通过悬停提示给出原因和解决办法。
- 通知服务在程序启动时主动读取一次 Windows 通知设置；之后每次发送通知前后继续复检，并保留实际投递失败后的降级。
- 当显示器已经关闭且事件明确选择在息屏/锁屏期间提醒时，发送通知前调用一次 `SetThreadExecutionState(ES_DISPLAY_REQUIRED)` 请求点亮锁屏画面；不持续占用电源请求，不解锁电脑，也不用于实际睡眠。
- 实际睡眠优先于息屏和锁屏策略；即使先息屏或锁屏再睡眠，也按照睡眠期间错过规则处理。
- 普通通知未处理时遇到锁屏或睡眠转为延迟，包含先息屏再进入锁屏或睡眠的顺序。
- Windows 监测器只报告锁屏、显示和睡眠事实，业务状态变化由 `ReminderEngine` 完成。

## 变更

- 新增固定事件系统策略、通知策略、全部暂停时长、全局暂停快照和系统状态模型。
- 调度器改用可替换 `TimeProvider`，继续只维护一个最近到期计时器。
- 新增 `ReminderEngine.Availability.cs`，实现分层阻止状态、限时全部暂停、错过去重与汇总、终止次数扣减和系统状态转换。
- 事件卡片中的息屏/锁屏下拉框接入实际逻辑；主页面增加限时全部暂停表单和倒计时。
- 托盘增加“快捷全部暂停”和“全部恢复”。
- 新增独立 Windows 活动监测器，监听会话锁定、显示状态和系统挂起/恢复。
- 后续修订下拉框滚轮路由，合并全部暂停/全部恢复按钮，增加 1 分钟快捷暂停和一秒悬停提示，重写全部恢复与全部重启筛选逻辑。
- 通知服务增加可用状态、原因和解决办法；构造时立即尝试读取 `ToastNotifier.Setting`，启动界面不再无条件显示已就绪，发送通知前后继续复检。未打包桌面进程不被允许预读设置时仍采用兼容回退，不提前禁用原本可工作的通知。
- 新增按需短时显示请求；通知请求只在逻辑层确认显示器已关闭且策略允许提醒时携带该意图。
- 更新 `docs/REQUIREMENTS.md`、`docs/EVENT_FORM_DESIGN.md`、`docs/REMINDER_LOGIC_DETAILS.md` 与 `docs/NEXT_STAGE_AVAILABILITY_PLAN.md`。
- Debug 与 Release 构建均为 0 个警告、0 个错误；25 项新状态测试和 18 项既有时间模型测试全部通过。
- 默认窗口、窄窗口、全局按钮、下拉滚轮、通知状态和悬停提示通过界面探针；通知发送器状态、短时显示请求和 Windows 监测器通过冒烟测试。

## 决策

- 按分层状态模型实现不可提醒闭环，Windows 回调不直接修改业务计时。（来源：U001）
- 全部恢复和全部重启采用最新的“只检查是否开启”语义；收起的下拉框不再滚轮改值；锁屏画面变黑时使用一次短时显示请求辅助展示通知。（来源：U002）
- Windows 通知状态在程序启动时主动检测，运行期间仍在发送通知时复检。（来源：U003）
- 本阶段继续不实现数据保存、启动恢复、完整退出、搜索、主题、自动更新和 MSIX。

## 后续事项

- 用户再次使用 `Win+L` 等待显示器变黑，验证短时显示请求能否在当前硬件、电源策略和 Windows 版本下重新点亮锁屏画面并展示通知。
- 用户关闭 Reminder 的 Windows 通知权限后重新启动程序，验证右下角能否在首次显示时直接标红为未就绪。
- 用户继续体验真实睡眠/唤醒，并根据结果修正 Windows 通知可见性或系统事件顺序问题。
- 后续再讨论下一阶段是否进入数据保存与启动恢复。

## 不确定项

- `ES_DISPLAY_REQUIRED` 的调用和返回值已验证，但自动化测试没有主动把用户显示器关闭；黑屏后的实际点亮效果仍受当前硬件、驱动和 Windows 电源策略影响，需要实机复核。
- 锁屏期间通知内容最终是否显示仍受 Windows 通知权限、锁屏通知设置和隐私设置控制；程序不会绕过系统设置。
