## 关键要点

- 项目是长期后台运行的 Windows 桌面提醒程序，支持休息眼睛、喝水和自定义事件。
- 核心方向包括轻量、稳定、低打扰、系统原生通知、独立事件计时、托盘后台运行、可配置启动行为和简洁现代的界面。
- 需求和架构不会一次确定，后续确认的任何需求变化都要同步进入 `docs/REQUIREMENTS.md`。
- 助手自己的功能或架构建议在用户确认前不得写入正式需求文档。
- 所有事件采用统一模型；“喝水”和“休息眼睛”仅为默认关闭且可删除的初始示例。
- 提醒时间改为固定间隔和指定时间重复两类；后者支持一次性、每天、每周、每月和每年，并允许保存位于过去的时间。
- Windows 通知需要直接提供“完成、延迟、跳过本次”，完成后从完成时刻重新计时。
- 实际睡眠或休眠最终不再提供用户策略，也不在期间发送提醒；唤醒后对期间到点事件只提示“已跳过”。继续、重新、暂停计时等策略只保留给息屏和锁屏。
- 已通过 Microsoft 官方文档确认 Windows App SDK 通知支持按钮；正在向用户说明适合本项目的桌面技术和部署流程。
- 通知必须使用 Windows 原生关闭入口、布局和按钮排列；通过通知按钮处理动作时不显示主面板。
- 用户要求记录事件驱动、单一最近到期计时器、隐藏界面时停止倒计时刷新等轻量化原则，并给出 CPU 与内存目标。
- 正式发布只采用自包含方式。综合用户授权和现有自动更新、卸载需求，选定自包含 MSIX 与 Windows App Installer，初始不提供便携版。
- 用户选择先使用 WPF，后台内存上限调整为 100 MB，理想目标为 60 MB。
- 通知关闭叉号按“跳过本次”处理；通知自行消失按“延迟”处理。
- 用户纠正执行顺序：当前先说明 Visual Studio 操作，在再次确认前不创建代码。
- 初期测试版本也必须采用可以作为正式实现基础继续演进的架构，不能只写一次性验证代码。
- 当前 `Reminder.slnx` 已包含 `src/Reminder.App/Reminder.App.csproj`；项目为 `net10.0-windows`、`WinExe`、已启用 WPF。
- 用户确认程序代码保持为一个 WPF 项目，内部划分 `UI`、`Logic`、名称待定的 Windows 交互、`System` 四个主要模块；`System` 负责配置与运行状态存储、联网检查版本和自动更新。
- Windows 交互模块最终命名为 `Windows`。模块间不设置僵硬的单向调用限制；`UI` 按需读取和显示，提醒业务数据由 `Logic` 修改，`Windows` 检测系统活动并通知 `Logic`。
- 用户通过托盘主动退出时需要保存全部恢复状态；固定间隔事件在下次启动时延续既有计时状态。软件未运行期间发生的提醒和暂停期间到达指定时间的提醒，在恢复时提示一次“已跳过”并按原规则继续。
- 用户进一步闭环了固定间隔与指定时间事件在软件未运行、暂停、睡眠、息屏和锁屏期间的差异化行为；确定错过提醒合并、无按钮通知、一次性事件结束、事件开关与暂停分离、离线冻结和精确时间边界。
- 固定间隔事件在不可提醒期间继续计时但抑制通知时，恢复后保持原有节奏；“已跳过”通知不显示下一次时间，但循环调度内部仍需计算。
- 延迟直接修改事件当前剩余时间，不设置独立延迟状态；过去的一次性或无未来计划事件提示后关闭，不使用“单次计划已处理”字段。
- 直接把关闭开关拨回开启时同时恢复；编辑关闭事件导致自动开启时仍保留暂停属性。
- 运行期间约每 1 小时低频保存，不要求每次操作即时写盘；异常退出造成小幅节奏回退已被接受。系统时间或时区变化不做额外历史校正。
- 最新资源目标为：界面显示时内存低于 160 MB、隐藏时低于 100 MB，两种状态 CPU 均低于 1%，安装包以不超过 300 MB 为可接受目标；指标允许弹性。
- 固定间隔暂停结束后继续剩余时间，重启时从 `0` 开始完整间隔；全局延迟时长默认 5 分钟并可修改。
- 通知自动消失时间是全局设置，默认 10 秒。通知自行消失按“延迟”处理并使用全局延迟时长再次发送同一次提醒；点击关闭叉号按“跳过本次”处理，程序需要区分两种关闭原因。
- 月度或年度计划遇到不存在的日期时跳过该周期。
- 每天首次启动检查一次新版本；检查失败保持安静，用户确认更新后若失败则显示软件内错误页面。托盘菜单和默认跟随系统主题也已经确定。
- 添加事件后立即出现一条默认事件，名称默认“新建事件”，允许重名，并使用隐藏的 `event id` 唯一识别。
- 单条事件按固定时间事件、指定时间事件切换表单；指定时间事件支持仅一次、每天、每周、每月、每年及相应日期、星期、月份、时间字段，所有事件都显示倒计时。
- 息屏和锁屏是随事件类型变化的事件属性；实际睡眠或休眠仍不提供用户选项。全部暂停影响所有事件，全部重启只影响符合条件的固定时间事件。
- 经 Microsoft 官方架构核对，Windows 原生通知不支持任意整体配色，仅有按钮的绿色 `Success`、红色 `Critical` 样式，因此不增加通知颜色字段。原生通知显示时长只提供 `short`、`long`，全局精确秒数仍需在通知接口选型时验证。
- 每条事件最终采用带底框、可横向滚动的双行卡片；第一行是名称、暂停/恢复、重启、秒级倒计时、开关、删除，第二行是类型动态表单和息屏、锁屏策略。暂停或关闭事件整体变淡。
- 新建自定义事件默认开启、不暂停、固定时间事件、45 分钟间隔、终止次数“不终止”。指定频率切换时按选择时刻的一小时之后初始化相应字段。
- 倒计时精确到秒并按天、时、分、秒分级显示；失效事件通常留空，每次启动有 5% 概率显示“弹一万遍反方向的钟”。
- 通知自动消失时间从事件属性改为设置页面中的全局值，默认 10 秒。
- 用户最终删除截止时间，只保留终止次数：完成或跳过扣减，关闭叉号属于跳过；延迟和自动消失不扣且同一次延迟提醒最终只扣一次；纯信息“已跳过”汇总对其中每个不同事件分别扣减一次；减到 0 后自动关闭并显示“不终止”。指定时间选择“仅一次”时隐藏终止次数设置。
- 息屏和锁屏正式共用一套策略。指定时间重启按钮置灰，默认频率“仅一次”，系统状态默认“不提醒”；第一行共六列，两个初始示例继续默认关闭。
- 所有允许用户自定义输入的表单都必须在接受、保存或参与计算前检查合法性，防止异常输入造成溢出攻击、崩溃或错误状态；具体字段边界与提示方式后续确定。
- 初步简易版本只需简单 UI 和最小运行逻辑，但必须可以继续扩展为完整功能。当前只讨论范围，不开始实现；UI 保留 Windows 的交互风格和高级感，同时允许自定义颜色及其他视觉细节。
- 首版最小闭环最终收紧为固定间隔事件的添加、倒计时、暂停/恢复/重启、隐藏面板后后台运行、Windows 通知及通知按钮处理；暂不实现保存、启动恢复、完整退出和主题切换，并需要验证通知接口是否能区分叉号与自动消失。
- 调度、界面和通知从开始分开；各模块维护自身变量，不建立巨大全局变量池。后台最近到期计时器与 UI 倒计时刷新计时器职责分离。
- 当前版本为 `0.0.0`，三段分别用于重大架构重构、新功能和 Bug 修复。
- 最终数据存储不能直接使用可读明文，并应检测篡改；`0.0.0` 首版不实现持久化。
- 用户最终确认未来使用 DPAPI 当前用户范围保护的版本化 JSON，采用 UTF-8 序列化、完整性检查、临时文件原子替换和必要备份；`0.0.0` 仍不实现持久化。
- 用户确认 `0.0.0` 只实现冷灰与低饱和靛蓝方向的单一浅色主题，并以 `docs/V0.0.0_IMPLEMENTATION_PLAN.md` 作为下一阶段编码入口。
