# 2026-07-28 - 优化主页漂浮层次与切页动画

## 摘要

用户复核主页和渲染模式后，要求增强主页漂浮层次、放大顶部选项卡、修复事件页返回主页时全局按钮闪烁、缩小右侧卡片并修复中间卡片裁边，同时把各圆环从零回到下一周期的动画改为约一秒回弹到接近满值。上述界面修改已经完成，并记录了用户在普通桌面上的硬件与软件渲染体验。

## 关键要点

- 共享全局按钮的闪烁来自主页和事件页之间切换时，对始终可见的操作区重复执行入场透明度与位移动画。
- 中间卡片右边框缺失来自卡片宽度、右侧突出偏移和容器内边距之和超过右侧槽位。
- 主页卡片现在明显小于主圆形，并使用轻量静态层次、悬停短距离抬升和缩放表达漂浮感，没有持续循环漂移动画或模糊阴影。
- 圆环改为对秒、分、时、天分量分别插值，避免总秒数跨模运算导致从零瞬间跳到接近满值；回弹最终落在实际分量，例如秒环 `59/60`。
- 用户确认软件渲染内存已经达到满意的预期附近，但交互会明显变卡；硬件优先在当前电脑仍超过 `1 GB`，以后计划换其他电脑复测。
- 用户接受界面交互期间的短时 CPU 上升，因为 QQ、微信等桌面软件也有类似现象；空闲和后台资源目标不变。

## 变更

- 更新 `src/Reminder.App/UI/Views/MainWindow.xaml`，放大顶级导航、压缩右侧卡片和槽位，并调整最小窗口品牌区。
- 更新 `src/Reminder.App/UI/Styles/Controls.xaml`，使用额外轻量边框层建立圆形和卡片的静态漂浮层次。
- 更新 `HomePresentationAnimator.cs`，增强卡片悬停抬升但继续使用短时 `RenderTransform`。
- 更新 `PageNavigationController.cs`，可见状态没有变化的共享操作区不再重复执行入场动画。
- 更新 `CountdownRingsControl.cs`，实现分量级约一秒回弹并避免完整满圈状态。
- 更新 `docs/REQUIREMENTS.md`、`docs/HOME_PAGE_DESIGN.md` 和 `docs/versions/NEXT_STAGE_HOME_NAVIGATION_VALIDATION.md`。
- Debug、Release 构建为零警告零错误；9 项逻辑、18 项调度、25 项不可提醒状态、16 项持久化和下一阶段专项测试通过。
- 主页悬停、点击定位、反向导航共享按钮稳定性、快速导航、空主页、事件页原有交互、最小窗口布局和圆环回弹专项探针通过。
- Release 软件渲染复测：主页可见工作集约 `175.6–179.5 MB`，私有内存约 `93.5–94.4 MB`，采样 CPU 为 `0–0.63%`；隐藏后工作集约 `18.0–24.3 MB`。

## 决策

- 当前不为可能由本机驱动或显示环境造成的硬件渲染高内存增加专门修复，先保留两种渲染模式并等待其他电脑复测。
- 软件渲染继续作为兼容选项，不因为内存较低就改成默认模式；其交互卡顿需要在后续性能优化中继续观察。
- 页面交互造成的短时 CPU 峰值当前可接受，空闲和后台 CPU 目标仍继续执行。
- 本次属于 `0.4.1` 之后的本地界面优化，没有获得版本号更新、提交或上传授权。

## 后续事项

- 在其他电脑，尤其是不同 GPU、驱动和显示器环境中复测硬件优先模式。
- 后续继续评估软件渲染下的页面动画与局部重绘，优先减少卡顿且不牺牲已经确认的视觉层次。

## 不确定项

- 当前尚不能确认本机硬件优先模式超过 `1 GB` 的根因，也不能据此推断其他用户设备的表现。
- 软件渲染卡顿的具体瓶颈尚未进行逐项性能剖析。
