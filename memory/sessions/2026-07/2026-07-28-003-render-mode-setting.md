## 摘要

用户针对本机 WPF 硬件渲染约 1 GB 的异常占用，询问无独立显卡是否是原因，并讨论在 Reminder 设置中切换硬件与软件渲染、运行时应用或切换后自动重启的可行性。随后正式确认渲染模式下拉框、默认值、重启提示和两条处理路径，并要求把该设置页面及其逻辑加入下一阶段。本次更新需求和设计计划，没有修改程序代码。

## 关键要点

- 本机实际具有 `Intel(R) Arc(TM) Graphics` 集成 GPU，WPF `RenderCapability.Tier` 为 2，说明 WPF 认为该设备支持完整硬件加速；没有独立显卡不是必然原因。
- 当前显示模式为 `2560×1600 / 120Hz`，显卡驱动为 `32.0.101.5768`。该驱动发布于 2024-07，明显早于 2026-07 的 Intel 通用驱动，旧驱动和显示环境组合是可疑因素但尚未证实。
- WPF 的公开 API 可以在当前进程设置 `ProcessRenderMode`，其中 `SoftwareOnly` 可强制软件渲染；所谓硬件模式实际上应是恢复 `Default`，由 WPF 和系统按能力选择，不能承诺强制硬件。
- 尽管官方允许运行时改变进程偏好，为了完整释放已经建立的图形资源、回收当前异常内存并让所有窗口从同一模式启动，产品设置更适合在保存状态后自动重启应用。
- 正式选项名称为“软件渲染（兼容模式）”和“硬件优先渲染”，使用下拉框，默认“硬件优先渲染”。
- 选择改变后立即保存并提示“更改此设置软件需要重启”，提供“立即重启软件”和“稍后自行重启”。
- 稍后自行重启不改变当前进程实际模式；以后退出但未重启时，下一次启动仍必须应用新设置。
- 用户随后把第二个按钮文案从“稍后重启软件”修正为“稍后自行重启”，所有当前规范以新文案为准。
- 主页现有构图能够支持软件渲染；下一阶段需要在两种模式下测量主页静止、圆环变化、悬停、页面切换和隐藏状态的 CPU 与内存。
