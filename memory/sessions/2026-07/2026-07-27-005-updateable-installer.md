## 摘要

用户要求明确确认是否存在一种 Windows 发布方式，可以同时实现软件内一键更新、标准安装与卸载，以及把运行数据留在软件自身目录。结论是可以：标准 MSIX 不适合该组合，但可以改用传统安装器加软件内更新模块。推荐优先研究 Inno Setup 负责选择安装目录、安装和卸载，Reminder 或轻量更新组件负责检查、下载和启动新版安装器；新版安装器只替换程序文件，保留相对 `Data` 目录。

## 关键要点

- 用户选择例如 `D:\Programs\Reminder` 后，程序、卸载器和 `Data` 都位于该目录体系，不必在 C 盘其他位置创建运行数据。
- Inno Setup 支持选择安装目录、生成自动卸载器、覆盖安装新版本、静默或极静默安装、关闭和重启应用。
- Inno Setup 可以只给 `{app}\Data` 子目录写权限，不给整个程序目录普通用户修改权限；官方文档明确认为给独立数据子目录写权限是安全的典型用法。
- 软件内更新流程可以是：检查版本、展示 `new`、显示更新内容、用户确认、下载并校验新版安装器、保存状态、退出主进程、静默覆盖安装、重新启动。
- 更新安装包不包含或不删除 `Data`，因此正式状态、备份和临时文件不受覆盖安装影响。
- 如果安装在普通用户可写目录，更新可以不请求管理员权限；如果安装在 `Program Files` 等受保护目录，Windows 可能显示 UAC，这是系统权限确认而不是程序额外步骤。
- Velopack 也能提供安装、更新和卸载，但默认安装到 `%LocalAppData%`，其一键安装器不提供普通目录选择向导；若优先满足用户自由选择 D 盘，Inno Setup 加更新模块更直接。
- NetSparkleUpdater Core 可以作为未来 WPF 更新模块候选，支持更新信息、发行说明、签名校验和下载安装器；是否引入仍需在自动更新阶段结合轻量化评估。
