# Reminder 设置页设计

- 文档状态：渲染模式、通知设置与恢复默认设置已实施；主题与启动设置已确认、尚未实施
- 最近更新：2026-07-29
- 关联主文档：`docs/REQUIREMENTS.md`
- 关联主页设计：`docs/HOME_PAGE_DESIGN.md`
- 关联实施计划：`docs/NEXT_STAGE_HOME_NAVIGATION_PLAN.md`、`docs/NEXT_STAGE_THEME_STARTUP_PLAN.md`

本文档记录设置页中已经确认的设置条目、交互和实现边界。已实施内容与只完成需求确认的内容分别标注，不能把尚未实施的设置显示成已经可用。

## 1. 页面范围

- 设置页属于“主页、事件、设置”三个顶级页面之一。
- 首轮设置页阶段不只创建空白容器，已经完整实现渲染模式设置及其生效逻辑。
- 设置页左侧提供设置标题导航列，右侧仍是承载全部设置的同一个纵向滚动页面；点击标题索引后平滑定位到对应设置区域。
- 定位完成后，目标设置卡片的底色短暂闪动一次，帮助用户快速确认位置。闪动使用短时、按需动画，完成、被新定位替代、离开设置页或隐藏窗口时立即清理，并遵循 Windows 客户区动画偏好。
- 通知延迟表单、超出事件间隔时的处理策略和 Windows 通知横幅时长已经纳入当前实现。
- 主题、开机自动启动和静默启动已纳入下一阶段确认范围，但尚未实施；版本检查和更新继续后移。

## 2. 渲染模式表单

- 设置项名称为“渲染模式”。
- 使用下拉框选择，不使用开关或分段滑块。
- 渲染模式下拉框与事件页共用统一的现代简约下拉框样式；控件本身、展开菜单、选中反馈和滚动条均不得回退到 WPF 默认的老式外观。
- 下拉框只包含以下两个选项：
  1. “软件渲染（兼容模式）”；
  2. “硬件优先渲染”。
- 默认值为“硬件优先渲染”。
- “硬件优先渲染”恢复 WPF 默认渲染偏好，由 WPF 和 Windows 选择实际渲染路径，不承诺强制使用 GPU。
- “软件渲染（兼容模式）”强制当前 Reminder 进程采用 WPF 软件渲染。

## 3. 更改后的提示

- 用户在下拉框中选择与已保存值不同的模式后，程序先保存新设置，再弹出提示框。
- 提示文字固定为：“更改此设置软件需要重启”。
- 提示框提供两个操作：
  1. “立即重启软件”；
  2. “稍后自行重启”。

### 3.1 立即重启软件

- 程序按照统一的软件重启流程处理，不为渲染模式创建绕过现有生命周期的特殊退出方式。
- 重启前保存事件配置、计时、暂停和其他需要恢复的运行状态。
- 新进程必须等待旧进程退出，并在创建任何 Reminder 窗口前读取和应用新渲染模式。
- 新进程随后按照正常启动恢复流程加载事件和运行状态。

### 3.2 稍后自行重启

- 当前进程保持启动时已经生效的渲染模式，不尝试运行时重建现有窗口或图形资源。
- 新选择已经保存，不因用户关闭设置页、隐藏主窗口或继续使用程序而丢失。
- 如果用户之后通过托盘退出而没有立即重启，下一次正常启动仍必须应用新选择。

## 4. 数据与职责边界

- 持久化模型使用稳定枚举或等价类型保存渲染模式，不把下拉框显示文字直接作为业务值。
- 旧存档中没有渲染模式字段时，按“硬件优先渲染”迁移。
- 渲染模式必须在第一个窗口和主要 WPF 图形资源创建前应用。
- `UI` 只负责展示下拉框、收集选择和显示重启提示。
- `System` 负责保存设置和协调应用重启。
- 应用启动层负责在窗口创建前把已保存值映射为 WPF 的默认渲染偏好或 `SoftwareOnly`。
- 渲染模式变化不得直接修改提醒事件、调度器、暂停状态或通知状态。

## 5. 主页的软件渲染兼容性

- 已确认的主页圆形、圆环、最近事件卡片和页面切换均可由 WPF 软件渲染管线完成，不要求修改产品构图或移除既有交互。
- 实现时优先使用短时 `RenderTransform`、透明度和局部重绘，不按帧修改宽度、边距等布局属性。
- 圆环只重绘实际变化的可见分量；页面隐藏或不再显示主页时停止主页逐秒视觉刷新。
- 避免在大面积区域持续使用模糊、复杂透明蒙版或高成本动态阴影；卡片层次优先使用边框、底色和静态轻量效果。
- 软件渲染模式下必须单独测量主页可见空闲、圆环逐秒变化、卡片悬停、页面切换和窗口隐藏后的 CPU 与内存。
- 如果测量未达到项目资源目标，应先优化绘制范围、图形缓存和视觉效果实现；是否减少已经确认的动画表现需要另行讨论，不在文档阶段擅自取消。

## 6. 验收重点

- 新安装或无渲染设置的状态默认显示“硬件优先渲染”。
- 两个下拉选项文字、顺序和保存值正确。
- 更改后显示正确提示和两个按钮。
- “立即重启软件”完成保存、退出、重新启动和状态恢复，且新模式从首个窗口开始生效。
- “稍后自行重启”不改变当前进程实际模式，退出后下一次启动能够应用新模式。
- 软件渲染下主页全部核心内容可以正常显示，圆环、文字、卡片和页面切换无乱码、缺失或明显错位。
- 窗口隐藏后停止无意义的主页渲染工作；软件渲染和硬件优先模式均记录可见与隐藏状态的 CPU、工作集、私有内存和托管堆结果。

## 7. 通知延迟设置（已实施）

### 7.1 统一通知延迟时间

- 设置项用于统一决定所有事件点击“延迟”以及通知自动消失后再次提醒前的等待时长，不允许单个事件分别设置。
- 界面说明简化为“设置通知延迟的时间。”，不在设置项下重复列出所有触发延迟的场景。
- 默认值为 5 分钟。
- 输入控件沿用固定时间事件提醒间隔的动态时长表单：
  - 小于 60 分钟时只显示“分钟”；
  - 达到 60 分钟后显示“小时、分钟”；
  - 达到 24 小时后显示“天、小时、分钟”；
  - 最大为 365 天，不显示“年”。
- 用户按 Enter 或焦点离开整个时长表单区域时，整组输入统一换算、自动进位并按照最终总时长重新展开或收起。
- 空分量按 0 计算；合计为 0、超过 365 天、包含非数字字符或可能造成溢出的输入不得应用，也不得写入持久化状态。

### 7.2 延迟时间超过事件提醒间隔时

- 设置页提供一个下拉选项。
- 选项一显示为“缩短为事件提醒间隔”：本次延迟缩短为该通知对应事件的提醒间隔时间。
- 选项二显示为“仍使用统一延迟时间”：即使统一通知延迟时间更长，本次仍使用统一通知延迟时间。
- 默认选择“缩短为事件提醒间隔”，延续当前取较小值的行为。
- 该策略只对提醒间隔小于统一通知延迟时间的固定时间事件生效；界面说明为“此选项只作用于提醒间隔小于上一选项设定时间的固定时间事件”。

### 7.3 与自动消失时间的边界

- 通知自行消失仍按“延迟”处理，并使用上述设置确定本次延迟时长。
- 全局通知自动消失时间使用下拉框，不使用任意数值输入框，也不复用通知延迟的天、小时、分钟动态表单。
- 下拉框只显示 Windows 实际提供并支持的 `Short` 与 `Long` 两档，界面说明约为 7 秒和 25 秒；当前默认选择较短档。
- 界面说明不重复“使用 Windows 支持的时长档位”，只说明横幅淡出后通知仍会进入通知中心。
- 横幅淡出使用 Windows 的 `TimedOut` 回调进入延迟逻辑，通知仍由 Windows 放入通知中心；程序不再运行另一套固定 10 秒横幅计时器。

## 8. 恢复默认设置（已实施）

- 设置页提供“恢复默认设置”按钮。
- 点击后不得立即恢复，必须先弹出确认菜单，明确询问用户是否恢复默认设置。
- 只有用户确认后才执行恢复；取消时保持全部设置不变。
- 设置页主界面说明为“恢复所有设置为默认，并且不会删除事件记录。”，不在卡片中逐项列出内部恢复范围。
- 当前实现恢复渲染模式和通知设置，不删除事件、暂停状态或搜索历史。
- 如果恢复操作改变了渲染模式，继续弹出既有重启提示，由用户选择“立即重启软件”或“稍后自行重启”。
- 下一阶段加入新设置后，恢复默认设置还应把主题恢复为“跟随系统”，并关闭开机自动启动和静默启动。
- 恢复默认设置继续保留事件、暂停状态和搜索历史。

## 9. 主题设置（已确认，尚未实施）

- 主题使用下拉框提供“跟随系统”“浅色”和“深色”三个选项，默认选择“跟随系统”。
- 手动切换主题后立即应用，不要求重启程序。
- 选择“跟随系统”后，程序响应 Windows 主题变化更新界面，不使用持续轮询。
- 主题必须覆盖主页、事件页、设置页、下拉菜单、搜索历史、提示框、确认框、禁用状态和危险操作等全部现有界面。
- 浅色主题整体采用白色与浅冷灰层次；深色主题使用炭黑色系，并同步调整文字、边框和交互状态以保证可读性。
- 主题切换不得改变事件调度、暂停、通知、持久化或渲染模式的业务语义。

## 10. 启动设置与单实例（已确认，尚未实施）

- 设置页增加“开机自动启动”开关和“静默启动”开关。
- “静默启动”旁显示小问号说明入口，悬停文字为“程序启动时以后台模式运行，不显示程序面板”。
- 启用静默启动后，程序仍完成数据恢复、调度、通知和托盘初始化，只是不显示主窗口；用户可以通过托盘打开主页。
- Reminder 采用单实例运行。程序已经运行时再次启动，不创建第二套提醒引擎或托盘图标，而是打开并激活已有进程的主页。
- 开机启动的 Windows 注册、取消注册和状态核对由 Windows 模块中的独立服务处理，UI 只提交用户选择。
- 主题、开机启动和静默启动设置都进入既有受保护状态与即时保存流程，并兼容旧状态文件。
