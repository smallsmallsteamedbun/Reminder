# Reminder 下一阶段：通知设置、事件搜索与设置页完善计划

- 规划日期：2026-07-28
- 基线版本：`0.5.1`
- 计划状态：范围已再次确认，等待用户完成备份后授权实施
- 实施授权：尚未授权；本轮只完成规划和需求归档
- 关联需求：`docs/REQUIREMENTS.md`
- 现有设置页：`docs/SETTINGS_PAGE_DESIGN.md`

## 1. 阶段判断

`0.5.1` 已经完成主页、事件页、设置页外壳、渲染模式设置，以及全部暂停单项恢复和事件表单显示修复。本阶段应继续补齐现有提醒链路中最常用、且已经形成明确产品规则的设置与查找能力：

- 把当前固定的通知延迟行为改成可配置但仍保持轻量的统一设置；
- 增加事件搜索与最近搜索记录，改善事件较多时的定位效率；
- 增加 Windows 支持的通知自动消失时长下拉设置；
- 完善设置页分组，并提供带确认的“恢复默认设置”入口；
- 对新增设置、搜索、持久化以及既有调度进行完整回归。

主题、开机启动、静默启动和自动更新会扩展不同的系统边界，本阶段继续不同时引入。

## 2. 实施范围

### 2.1 设置模型、迁移与保存

- 在应用设置中加入统一通知延迟总分钟数，默认 5 分钟。
- 加入“事件提醒间隔短于统一延迟时”的类型化策略；显示选项为“缩短为事件提醒间隔”和“仍使用统一延迟时间”，默认前者。
- 加入通知自动消失时长设置；值只能来自 Windows 实际支持的选项，不保存任意输入数字。
- 加入最多 5 条最近事件搜索记录所需的运行状态；是否写入持久化设置在确认跨重启规则后决定。
- 设置文档升级结构版本；旧状态迁移为确认的默认值。
- 设置修改继续走现有串行即时保存；非法界面草稿不得覆盖上一份合法值。
- 恢复默认设置时也通过同一设置服务和保存入口提交，不建立第二份配置。

### 2.2 可复用的动态通知延迟表单

- 把固定时间事件已有的“分钟—小时—天”换算和校验整理成小型可复用逻辑，供通知延迟设置使用。
- 默认 5 分钟时只显示“分钟”；达到 60 分钟后显示“小时、分钟”，达到 24 小时后显示“天、小时、分钟”。
- 最大为 365 天，不显示“年”。
- 按 Enter 或焦点离开整个表单区域时统一确认；空分量按 0 处理，合计为 0、超过上限、非数字或溢出输入不应用。
- 共享范围只包含时长编辑与校验，不把调度状态或通知业务写入可复用视觉控件。

### 2.3 通知设置与提醒逻辑

- 设置页增加“通知”分组，包含统一通知延迟表单、延迟超出事件间隔时的策略下拉框和通知自动消失时长下拉框。
- 通知中的“延迟”、通知自动消失、以及锁屏或睡眠时对未处理通知执行的延迟处理，都通过同一个“解析本次延迟时长”入口。
- 继续遵守“直接修改当前剩余时间、不建立独立延迟字段、延迟不扣终止次数”的规则。
- 通知自动消失时长下拉框根据实际 Windows 通知接口能力提供选项，不用分钟—小时—天输入框替代。
- 自动消失时长的具体 Windows 选项、初始选中项和系统设置同步方式，实施开始时先验证接口能力，再按确认需求映射。

### 2.4 事件搜索与搜索历史

- 事件页顶部加入事件名称搜索框。
- 搜索忽略英文字母大小写和首尾空格；连续空格分隔多个字段，字段间采用“并且”关系。
- 搜索框非空时显示清空叉号。
- 搜索框获得焦点或展开时显示最近 5 条搜索记录；每条记录可单独删除，底部可以清空全部记录。
- 搜索结果只是一份保留原顺序的界面投影，不复制事件业务状态，不影响调度、开关、暂停或持久化。
- 点击“添加事件”时先清空搜索，再新增、定位并高亮新事件。
- 名称更改只有在按 Enter 或离开名称框并成功应用后才更新筛选结果。
- 全部暂停、全部恢复和全部重启始终作用于全部符合条件的事件，不受当前搜索结果限制。

### 2.5 设置页布局与恢复默认设置

- 按统一的卡片、分组、标签、说明、输入框、下拉框、间距和错误状态整理渲染模式与通知设置。
- 默认窗口和允许的最小窗口下均应可阅读、可操作；超出高度时使用现有风格的滚动方式。
- 设置页增加“恢复默认设置”按钮。
- 点击后先显示确认菜单；确认后才恢复，取消则不更改任何设置。
- 恢复范围、是否清除搜索历史，以及需要重启才能生效的设置如何提示，实施前继续确认，不能由代码自行猜测。

## 3. 实施顺序

### 阶段 A：接口能力和剩余边界

- 验证当前 Windows 通知接口可提供或接受哪些自动消失时长，以及能否读取系统当前值。
- 确认延迟超出事件间隔策略对指定时间循环事件的适用方式。
- 确认搜索历史的写入、去重、排序和跨重启规则。
- 确认恢复默认设置的覆盖范围和重启提示。

### 阶段 B：类型化设置和状态迁移

- 增加通知延迟、延迟策略、自动消失选项和搜索历史的数据结构。
- 完成旧状态迁移、即时保存、退出保存和启动恢复。
- 先用逻辑测试覆盖默认值、旧版本迁移、非法值拒绝和持久化往返。

### 阶段 C：通知延迟共享逻辑

- 完成动态时长编辑与整组校验。
- 建立单一的本次延迟解析入口，并接入所有已有延迟来源。
- 验证延迟后仍属于同一次提醒、终止次数不扣减、重启后恢复正确剩余时间。

### 阶段 D：设置页和事件搜索

- 完成通知设置分组、Windows 时长下拉框和恢复默认确认。
- 完成事件搜索、清空按钮、最近 5 条历史、单条删除和全部清空。
- 复用现有事件卡片和事件模型，不创建第二套业务对象。

### 阶段 E：整体回归与资源复核

- 回归托盘打开主页、全部暂停、全部恢复、版本显示、退出保存和窗口隐藏后台运行。
- 回归固定与指定时间调度、通知操作、自动消失、锁屏或睡眠处理、全部操作和最近到期计时器。
- 回归新设置即时保存、一小时低频保存、退出保存、启动恢复、`state.dat`/`state.bak` 回退及旧状态迁移。
- 分别在“硬件优先渲染”和“软件渲染（兼容模式）”下检查设置页、搜索、事件滚动、页面切换、CPU 和内存。

## 4. 本阶段暂不实现

- 主题、开机自动启动和静默启动；
- 版本检查、`new` 标记、自动下载和覆盖更新；
- Inno Setup 安装、卸载及卸载时保留或删除 `Data`；
- 新提醒类型、循环频率、通知操作或统计页面；
- 改变当前硬件优先默认渲染策略。

## 5. 验收标准

- 旧版状态能够迁移，新增设置和搜索历史能够保存并在重启后正确恢复。
- 通知延迟表单在分钟、小时、天三个形态间正确转换；非法草稿不改变 Logic 或磁盘中的上一份合法值。
- 所有已有延迟入口使用相同策略，且延迟仍不扣减终止次数。
- 通知自动消失下拉框只提供 Windows 支持的选项，不允许任意数字进入持久化状态。
- 单字段、多字段、大小写和空格搜索结果正确；清空和历史管理操作正确。
- 搜索不会改变事件身份、顺序、调度、开关、暂停和全局操作范围。
- 恢复默认设置只有确认后生效，取消不产生持久化更改。
- 设置页在默认窗口和最小窗口下没有乱码、截断、明显错位或无法操作的控件。
- 两种渲染模式下，托盘、调度、持久化、通知、全部操作和页面导航回归通过，且没有新增持续轮询或空闲动画。
- Debug、Release、迁移、通知延迟、搜索、界面和既有核心测试全部通过。

## 6. 实施前仍需明确的边界

- 延迟超出事件间隔策略是否只适用于固定时间间隔事件。
- Windows 通知接口的实际自动消失时长选项、默认选中项和系统设置同步方式。
- 搜索历史何时写入、相同内容如何去重、展示顺序和是否跨重启保留。
- 搜索无结果状态的最终视觉。
- 恢复默认设置覆盖哪些设置、是否清除搜索历史，以及渲染模式等设置的重启提示。
