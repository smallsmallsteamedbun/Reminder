## 2. `0.0.0` 目标

首版完成一条真正运行的固定时间间隔提醒闭环：

```text
添加固定间隔事件
→ 开始倒计时
→ 暂停、恢复或重启
→ 隐藏主面板后继续后台运行
→ 到点发送 Windows 通知
→ 用户通过通知完成、延迟或跳过
→ Logic 更新当前事件并重新调度
```

首版是架构和核心技术路径验证版。它应当看起来像一个完整的小型 Windows 程序，但不承担持久化和完整产品功能。

## 3. 首版实现内容

### 3.1 UI

- 单一浅色主题：浅冷灰页面、白色卡片、低饱和靛蓝主色。
- 顶部结构，不使用宽侧边栏。
- 顶部显示 `Reminder`、版本号 `0.0.0` 和窗口控制。
- 页面操作区显示“添加事件”、全部暂停、全部恢复和全部重启。
- 主体显示可横向滚动的双行事件卡片。
- 首版事件卡片只呈现已经实现的固定时间间隔字段，不显示指定时间、终止次数、息屏/锁屏策略和主题切换等无效控件。
- 使用 Windows 风格的悬停、按下、禁用和键盘焦点反馈，并使用克制的短过渡。

### 3.2 固定时间间隔事件

- 显示默认关闭的“喝水”和“休息眼睛”示例事件。
- 添加和删除自定义事件。
- 编辑事件名称和以分钟为单位的固定提醒间隔。
- 事件名称允许重名，内部使用不可见的 `event id` 区分。
- 支持开启、关闭、暂停、恢复和重启。
- 支持全部暂停、全部恢复和全部重启。
- 显示精确到秒的只读倒计时。
- 所有自定义输入在交给 `Logic` 前执行合法性检查；非法输入不应用。

### 3.3 后台和通知

- 主面板隐藏后，后台调度继续运行。
- 系统托盘提供重新显示主面板的入口。
- 首版不提供完整退出菜单项；开发阶段通过 Visual Studio 停止调试或结束进程。
- 使用真实的 Windows 系统通知。
- 普通通知提供“完成”“延迟”和“跳过本次”。
- 完成、延迟和跳过的结果回到 `Logic`，再由 `Logic` 更新事件状态。
- 首版必须验证所选 Windows 通知接口能否区分：
  - 用户点击关闭叉号；
  - 通知没有用户操作而自动消失。
- 如果平台接口无法准确区分，应记录验证环境、接口、观察结果和限制，不在代码中伪造已经区分的结果。

## 4. 首版明确不实现

- 指定时间事件及每天、每周、每月、每年循环。
- 终止次数。
- 息屏、锁屏、睡眠和休眠处理。
- 错过提醒汇总。

- 版本联网检查、`new` 标记、自动更新和正式 MSIX 发布。

未实现功能不显示可操作但无效的控件。

## 5. 模块和边界

继续使用一个 WPF 项目，并在项目内部按职责组织：

```text
src/Reminder.App/
├─ UI/
│  ├─ Views/
│  ├─ ViewModels/
│  ├─ Controls/
│  └─ Styles/
├─ Logic/
│  ├─ Models/
│  ├─ Scheduling/
│  └─ Services/
├─ Windows/
│  ├─ Notifications/
│  ├─ Tray/
│  └─ Windowing/
└─ System/
   └─ AppInfo
```

上述目录是首版实施映射，不要求为了目录完整而创建没有实际用途的空类。

必须保持三个边界：

1. 调度逻辑不直接操作 WPF 控件。
2. 调度逻辑不直接实现或调用具体 Windows 通知 API。
3. UI 不直接修改后台计时器，只把用户意图交给 `Logic`。

状态所有权规则：

- `Logic` 维护提醒事件和计时状态。
- `UI` 通过数据绑定读取可显示状态，并向 `Logic` 发送操作。
- `Windows` 维护托盘、窗口隐藏和通知平台对象，并把平台结果交回 `Logic`。
- `System` 在首版只提供版本等不可变应用信息；未来再增加存储实现。
- 不建立巨大的全局变量池。版本号等固定信息可以全局只读，事件运行状态不能成为任意模块都可修改的全局数据。

## 6. 计时模型

- 后台只有一个提醒调度计时器，始终等待当前最近到期的事件。
- 添加、删除、开启、关闭、暂停、恢复、重启、完成、延迟或跳过事件后，重新寻找最近到期事件并设置该计时器。
- UI 可见时使用一个轻量 UI 刷新计时器，每秒更新倒计时显示。
- UI 刷新计时器不决定提醒是否到点，也不修改调度状态。
- UI 隐藏时停止刷新计时器，后台调度计时器继续工作。

## 7. 通知结果模型

通知平台边界至少需要把以下业务结果交给 `Logic`：

- 完成；
- 延迟；
- 跳过本次；
- 用户关闭通知；
- 通知自动消失。

用户关闭通知最终映射为跳过，通知自动消失最终映射为延迟。平台层先保留不同结果，再由 `Logic` 执行业务语义，避免把 Windows API 细节混入调度器。

## 8. UI 实施基线

- 首版基于原生 WPF 控件和项目内样式资源实现，不为了首版视觉引入大型 UI 运行环境。
- 颜色、字号、间距、圆角和控件状态集中在样式资源中，不散落硬编码在各个卡片。
- 事件卡片保持两行结构，以便后续增加指定时间和系统状态字段时继续扩展。
- 暂停或关闭事件降低视觉强调，但文字仍需清晰可读。
- 删除操作保持克制，只有悬停或确认危险操作时进入红色状态。
- 暂未实现的设置入口和主题入口不显示。

## 9. 未来持久化设计

`0.0.0` 不读写磁盘，但 `System` 模块未来采用以下已确认方案：

```text
版本化状态对象
→ System.Text.Json 序列化为 UTF-8 字节
→ Windows DPAPI CurrentUser 整体保护
→ 写入临时文件
→ 原子替换正式 state.dat
→ 必要时保留恢复备份
```

- 加载时必须先通过 DPAPI 解密和完整性检查。
- 解密、完整性检查、反序列化或业务校验失败时，不把数据交给 `Logic`。
- JSON 内部使用独立的数据结构版本，以便未来迁移。
- 数据保护绑定当前 Windows 用户和本机环境，接受用户配置丢失或跨机器无法解密的限制。
- 最终保存位置、备份触发条件、损坏提示和迁移流程留到持久化版本实施。

## 10. 实施顺序

1. 整理现有 WPF 模板，建立四模块目录和样式资源入口。
2. 建立不可变应用信息和 `0.0.0` 版本显示。
3. 建立固定时间间隔事件模型和 `Logic` 操作入口。
4. 实现单一最近到期调度和 UI 秒级刷新分离。
5. 实现顶部页面、全局操作和固定间隔事件卡片。
6. 实现输入校验及错误状态展示。
7. 实现窗口隐藏、托盘入口和后台继续运行。
8. 接入 Windows 原生通知及按钮回调。
9. 验证关闭叉号与自动消失是否可以区分，并记录结果。
10. 完成首版手工验收和资源占用观察。

## 11. 首版验收标准

- 程序以无控制台窗口的 WPF 应用启动。
- 页面显示 `Reminder 0.0.0`，采用确认的单一浅色视觉方向。
- 可以添加至少两个互不影响的固定时间间隔事件。
- 合法输入可以应用，非法输入不会进入调度。
- 每个事件可以独立开启、关闭、暂停、恢复和重启。
- 全部暂停、全部恢复和全部重启作用正确。
- UI 倒计时精确到秒；隐藏面板后停止界面刷新，后台提醒仍能按时触发。
- 同一时刻到点的不同事件分别发送通知。
- 完成、延迟和跳过通知操作能改变对应事件的后续状态。
- 系统托盘可以重新显示主面板。
- 已完成通知关闭叉号与自动消失的可区分性验证并留下结论。
- 运行过程中不写入持久化配置或状态文件。
- 未实现功能不以可点击的空壳控件出现在界面中。

## 12. 编码前剩余的非阻塞参数

以下参数不会改变整体架构，可在实现对应控件时再确认：

- 事件名称的最大长度。
- 固定提醒间隔允许的最大分钟数。
- 输入校验失败时采用就地提示、边框提示还是组合提示。
- 卡片各列的最终宽度、间距、圆角和精确颜色值。
- Windows 通知接口验证后的实际限制。

这些参数未确定不妨碍开始建立模块、模型、调度器和页面框架，但在完成相应功能验收前必须闭环。
