# Reminder `0.1.1` 验证记录

- 验证日期：2026-07-24
- 版本：`0.1.1`
- 结论：本次功能与体验优化已完成首轮验证

## 已验证内容

- 固定间隔短于全局延迟时长时，延迟采用固定间隔；长间隔事件仍采用默认 5 分钟。
- 通知横幅自动消失后进入延迟倒计时，但通知仍保留在 Windows 通知中心。
- 通知中心保留的通知仍包含“完成”“延迟”“跳过本次”三个操作。
- 下一次提醒出现时会移除同一事件的旧通知，避免重复堆积。
- 新增事件位于可见区域之外时，事件列表会自动定位并高亮新卡片。
- 鼠标位于事件卡片内部时，滚轮仍可纵向移动事件列表。
- 鼠标滚轮和新增事件定位均经过连续中间位置，不再直接跳变；新增事件在定位结束后才开始高亮。
- 删除命令先发出确认请求，只有确认后才移除事件；取消不会改变事件数据。
- 主界面删除按钮和确认框“确定”按钮均采用红色危险样式。
- 确认删除后，被删除卡片先进行短暂淡出，下方可见卡片通过平移动画填补空位。
- 版本号已经从右上角移动到左上角程序名称旁。
- 点击通知中心内保留通知的正文时，激活参数会重新展示同一提醒；正文点击本身不产生完成、延迟或跳过结果。
- 页面显示版本 `0.1.1`，窄窗口下未发现中文乱码或新增排版遮挡。

- Logic 回归测试全部通过。
- 新事件平滑定位、到达后高亮和鼠标滚轮平滑滚动测试通过。

- 删除重排动画检查确认存在连续中间位置；动画结束后没有残留 `RenderTransform` 或活动动画状态。

- 程序级正文激活测试确认：正文点击只重新展示通知；随后点击“完成”仍能产生正确业务结果。
- Debug 和 Release 构建均为 0 个警告、0 个错误。

## 说明

本次等待窗口内未收到“从通知中心点击正文，再在重新弹出的通知中点击完成”的人工点击回调，原因可能是未发生点击或测试桌面的交互限制，因此没有把这一整条人工实机链路标记为通过。真实通知历史已确认正文重新展示参数和三个按钮存在，程序级激活测试已经验证重新展示与后续“完成”的处理链路。

当前版本的删除淡出与卡片重排动画仍通过统一动画辅助组件显式设置最高 60 帧，不能充分利用 100 Hz、120 Hz、144 Hz 等高刷新率屏幕。滚轮平滑滚动已经依据实际经过时间计算，不依赖固定的 `1/60` 秒步长。下一阶段将移除普通界面动画的固定 60 帧上限，并验证不同刷新率以及多显示器切换时的动画时长一致性；此项尚未在 `0.1.1` 代码中实施。

Windows 平台能力依据：

- `ToastNotification.SuppressPopup=true` 会将通知静默放入通知中心：<https://learn.microsoft.com/en-us/uwp/api/windows.ui.notifications.toastnotification.suppresspopup>
- 相同 `Tag` 和 `Group` 的新通知可以替换已有通知，并可通过 `SuppressPopup` 避免再次弹出横幅：<https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/toast-progress-bar>
