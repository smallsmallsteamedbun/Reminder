# 主页、多页面导航与渲染模式阶段验证

- 验证日期：2026-07-28
- 基线版本：`0.4.1`
- 归档版本：`0.5.0`
- 文档性质：阶段实施与验证记录，现已纳入 `0.5.0`

## 已完成范围

- 建立“主页、事件、设置”三个顶级页面和居中导航。
- 将原有事件列表完整迁入事件页，并保留输入、滚动、新建定位、删除确认和高亮交互。
- 主页只读展示最多三个最近事件，支持稳定排序、固定卡片槽位、悬停预览、点击定位和无运行事件状态。
- 实现大型圆形计时器以及秒、分、时、天和超过 365 天的彩色圆环。
- 实现按需卡片、圆形和页面切换动画；快速连续导航以最后选择的页面为目标。
- 设置页实现“软件渲染（兼容模式）”与“硬件优先渲染”，设置立即保存。
- 实现“更改此设置软件需要重启”提示、“立即重启软件”和“稍后自行重启”。
- 渲染模式写入版本化状态；旧版状态自动使用“硬件优先渲染”。
- 立即重启会先保存状态，新进程等待旧进程退出后再加载状态并创建窗口。

## Release 资源初测

测试设备为当前无独立显卡的 Windows 设备。数值为短时完整应用探针结果，包含主窗口、提醒逻辑、通知、托盘、系统活动监测和持久化启动流程；CPU 采用占整机逻辑处理器总能力的比例。

| 模式与状态 | 稳定工作集 | 私有内存 | 托管堆 | 稳定 CPU |
| --- | ---: | ---: | ---: | ---: |
| 硬件优先，主页可见 | 约 `1089 MB` | 约 `1005 MB` | 约 `4.5 MB` | 约 `0.07–0.21%` |
| 软件兼容，主页可见 | 约 `176 MB` | 约 `93.5 MB` | 约 `4.5 MB` | 约 `0.07–0.14%` |
| 硬件优先，窗口隐藏 | 约 `24 MB` | 约 `1006 MB` | 约 `4.6 MB` | 约 `0–0.07%` |
| 软件兼容，窗口隐藏 | 约 `24 MB` | 约 `93.6 MB` | 约 `4.6 MB` | 约 `0–0.07%` |

说明：

- 切换软件渲染明显消除了当前设备上约 1GB 的 WPF 图形工作集现象。
- 窗口隐藏后工作集会在一次回收后降到约 `18–24 MB`；隐藏瞬间的过渡样本不代表稳定值。
- 软件模式的可见工作集约比 `160 MB` 理想目标高 `16 MB`，尚未完全达到理想值；后台工作集和稳定 CPU 已满足当前弹性目标。
- 硬件优先结果只代表当前设备，不能直接推断有独立显卡设备的表现，后续仍需进行其他设备对照。

## 用户普通桌面复测

- 硬件优先模式的内存仍超过 `1 GB`，与短时探针结论一致；当前尚不能确定是否由本机图形驱动或显示环境导致。
- 用户暂不要求针对可能的驱动原因继续修复，因为无法保证最终用户都会更新驱动；后续计划在其他电脑上复测硬件优先模式。
- 软件渲染的内存已经降低到用户满意的预期范围附近，但页面交互会出现可感知卡顿，说明该模式更适合作为兼容选项而不是无代价的默认替代。
- 硬件优先和软件渲染在页面交互期间都会出现明显的短时 CPU 上升。用户对比 QQ、微信后确认同类桌面软件也存在这一现象，当前接受交互峰值，不把它视为单独故障；仍继续约束空闲和后台 CPU。

## 后续优化方向

- 优先继续缩小主页可见时的 WPF 工作集和局部重绘范围。
- 在有独立显卡的设备上复测硬件优先模式。
- 后续增加其他设置项时继续复用现有设置服务、版本化状态和统一重启流程。

## 主页视觉优化后的资源复核

- 2026-07-28 在增加轻量静态层次、卡片悬停抬升和约一秒圆环回弹后，再次运行 Release 软件兼容模式完整应用探针。
- 主页可见工作集约 `175.6–179.5 MB`，私有内存约 `93.5–94.4 MB`，采样 CPU 为 `0–0.63%`。
- 窗口隐藏并完成回收后工作集约 `18.0–24.3 MB`，采样 CPU 为 `0–0.28%`。
- 本次视觉优化没有引入模糊阴影、持续漂浮时钟或长期动画；短时资源结果与优化前处于同一范围，仍满足后台和 CPU 弹性目标。
