# 0.4.0 内存诊断记录

- 日期：2026-07-28
- 范围：不附加 Visual Studio 调试器的本机 Debug、Release 和纯净 WPF 对照测试

## 测量结果

| 场景 | 工作集 | 私有内存 | 托管堆 |
| --- | ---: | ---: | ---: |
| Reminder Release，硬件渲染，窗口可见 | 约 1110–1114 MB | 约 1031–1032 MB | 约 7 MB |
| Reminder Debug，硬件渲染，窗口可见 | 约 1107–1170 MB | 约 1031–1081 MB | 约 7–8 MB |
| Reminder Release，硬件渲染，窗口隐藏并整理工作集 | 约 14–22 MB | 约 1032 MB | 约 7 MB |
| 纯净 .NET 10 WPF 空白窗口，硬件渲染 | 约 1043 MB | 约 993 MB | 约 1.5 MB |
| 纯净 .NET 10 WPF 空白窗口，软件渲染 | 约 131 MB | 约 82 MB | 约 1.5 MB |
| Reminder Release，软件渲染，窗口可见 | 约 180–184 MB | 约 98 MB | 约 7 MB |
| Reminder Release，软件渲染，窗口隐藏并整理工作集 | 约 19–25 MB | 约 98 MB | 约 7 MB |

## 结论

- 本机 1 GB 级占用不是 Visual Studio 调试器单独造成的，Debug 和 Release 在脱离 Visual Studio 后结果接近。
- 纯净空白 WPF 窗口在本机硬件渲染路径下同样接近 1 GB，而切换软件渲染后显著下降；因此主要来源是本机 WPF 硬件渲染与显卡、驱动或显示环境的组合，不是 Reminder 的事件数量、倒计时逻辑或托管对象泄漏。
- Reminder 自身托管堆约 7 MB。窗口隐藏后的工作集能够降至约 25 MB，但硬件渲染模式下私有提交仍然偏高。
- 项目当前保留 `REMINDER_SOFTWARE_RENDERING=1` 诊断开关；本次没有把软件渲染改为默认，因为软件渲染可能增加 CPU 使用并影响后续动画，需要结合更多设备测量后再决定正式策略。
