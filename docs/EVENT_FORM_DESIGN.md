# Reminder 单条事件表单设计

- 文档状态：持续讨论与迭代
- 最近更新：2026-07-23
- 关联主文档：`docs/REQUIREMENTS.md`
- 关联逻辑细节：`docs/REMINDER_LOGIC_DETAILS.md`

本文档记录单条事件的界面结构、字段、默认值、动态表单、运行状态和操作逻辑。本文优先采用最近一次确认；尚不能由现有规则唯一确定的内容集中列在第 10 节，不在正文中擅自补全。

## 1. 事件列表和卡片结构

- 主页面采用顶部结构，不使用占用较多横向空间的宽侧边栏。
- 顶部区域显示程序名称、版本号、设置入口和窗口控制；下方显示页面标题、“添加事件”和全局暂停、恢复、重启操作；主体显示事件卡片列表。
- 整体以 Windows 的按钮交互、焦点和状态反馈为基础，但不完全复刻 Windows。
- 当前自定义视觉方向使用冷灰底色、低饱和靛蓝主色和有轻微层次差异的卡片表面。
- `0.0.0` 初步简易版本只实现这一方向的单一浅色主题，不显示尚未实现的主题切换入口。
- 事件在列表中一条一条显示。
- 事件列表支持使用鼠标滚轮上下滚动；鼠标位于单条事件的横向滚动区域上时，滚轮仍用于纵向移动事件列表。
- 每条事件是一个独立的带底框区域，使不同事件呈现为一栏一栏的卡片。
- 单条事件内部字段横向排列。
- 为避免非全屏窗口横向空间不足，每条事件允许通过横向滚动条拖动查看。
- 每条事件分成上下两行，降低单行长度和拥挤程度。
- 暂停或关闭的非活动事件整体显示得更淡；活动事件保持正常显示强度。

## 2. 添加事件和内部身份

- 用户点击“添加事件”后，列表立即新增一条使用默认属性的事件。
- 如果新事件位于当前可见范围之外，列表自动滚动到该事件；新事件卡片的底框短暂高亮，帮助用户确认新增位置。
- 每条事件具有一个不向用户显示的内部 `event id`。
- 保存、修改、删除和调度都使用 `event id` 识别事件，不用名称识别。
- 事件名称允许重名。

目前已经确认的新建自定义事件默认值：

| 属性 | 默认值 |
| --- | --- |
| 事件名称 | `新建事件` |
| 暂停状态 | 不暂停 |
| 暂停/恢复按钮文字 | `暂停` |
| 事件类型 | 固定时间事件 |
| 固定提醒间隔 | 45 分钟 |
| 终止次数 | 不终止 |
| 开启/关闭 | 开启 |

首次安装时提供的“喝水”和“休息眼睛”示例事件继续默认关闭。它们的具体预设参数以后再讨论；“新建自定义事件默认开启”不改变这两个初始示例。

### 2.1 通用输入校验

- 单条事件中所有允许用户自行填写的表单都必须检查输入是否合法。
- 输入必须在保存或参与提醒计算前通过校验；校验失败时不得应用本次输入。
- 非法格式、异常长度或过大数值不得导致数值溢出、程序崩溃或事件进入错误状态。
- 本要求适用于事件名称、固定提醒间隔、日期与时间等自定义输入字段。
- 各字段允许的具体格式、最大长度、数值范围和界面提示方式后续逐项确定。

## 3. 第一行：名称、状态、操作和倒计时

第一行按当前描述依次包含以下功能块。

### 3.1 事件名称

- 第一列。
- 使用文本框。
- 用户点击文本框即可直接修改。
- 默认文字为“新建事件”。

### 3.2 暂停/恢复

- 第二列。
- 使用一个根据状态切换文字的按钮。
- 事件正在运行时显示“暂停”。
- 点击“暂停”后事件暂停，按钮文字切换为“恢复”。
- 点击“恢复”后事件恢复，按钮文字切换为“暂停”。
- 新建事件默认不暂停，因此默认显示“暂停”。

### 3.3 重启

- 第三列。
- 按钮文字固定为“重启”。
- 对符合条件的固定时间事件，点击后清除当前一轮已经经过的时间，从完整的提醒时间间隔重新开始倒计时。
- 指定时间事件不能重启；切换为指定时间事件后，第一行中的“重启”按钮保留位置但置灰，不能点击。

### 3.4 倒计时

- 第四列。
- 只读，用户不能修改。
- 表示距离该事件下一次提醒还有多久。
- 所有仍有未来提醒的事件都显示倒计时，包括固定时间事件和指定时间事件。
- 显示精度为秒，替代此前精确到分钟的旧想法。

显示规则：

1. 大于或等于 1 天：`DD天HH时MM分SS秒`；
2. 大于或等于 1 小时且小于 1 天：`HH时MM分SS秒`；
3. 小于 1 小时：`MM分SS秒`；
4. 天数不设显示上限，例如半年可以显示为 `183天……`。

已经失效、未来不会再发生的事件：

- 通常不显示倒计时；
- 每次程序启动时为每条失效事件随机计算一次；
- 有 5% 概率在倒计时位置显示彩蛋文字“弹一万遍反方向的钟”；
- 本次启动期间保持该次计算结果，下次启动重新计算。

### 3.5 开启/关闭

- 第五列。
- 使用开启/关闭滑块。
- 新建自定义事件默认选择开启。
- 切换为关闭时复用单项暂停逻辑。
- 从关闭直接切换为开启时，同时恢复事件。

### 3.6 删除

- 第六列。
- 用于删除当前事件。
- 初始示例事件和自定义事件都允许删除。

## 4. 第二行第一列：事件类型和时间设置

该区域先固定显示一个事件类型滑块：

- 左侧：固定时间事件；
- 右侧：指定时间事件；
- 默认停在左侧“固定时间事件”；
- 滑块下方的表单根据所选事件类型动态变化。

### 4.1 固定时间事件

#### 提醒时间间隔

- 使用输入框。
- 单位固定为分钟。
- 默认值为 45 分钟。

#### 终止次数

- 表示再提醒多少次后自动关闭事件。
- 使用下拉菜单。
- 选项为：
  - 不终止；
  - 1 次；
  - 2 次；
  - 依次增加；
  - 100 次。
- 最大值为 100 次。
- 默认选择“不终止”。
- 选择有限次数时，界面显示剩余次数。
- 只有当前普通提醒最终被“完成”或“跳过本次”时才扣减 1 次。
- 点击“延迟”不扣减；延迟后再次出现仍是同一次提醒，最终完成或跳过时总共只扣减 1 次。
- 点击通知关闭叉号属于“跳过本次”，因此扣减 1 次；通知自行消失属于“延迟”，自动消失时不扣减。
- 恢复时显示的纯信息“已跳过”汇总也扣减终止次数：汇总中每个不同事件分别扣减 1 次，同一事件在同一段不可提醒状态中错过多次只汇总并扣减 1 次。
- 有限次数减到 0 后，事件自动关闭；由于下拉菜单没有“0 次”，关闭后该字段显示“不终止”。
- 事件已经关闭，因此显示“不终止”不会继续触发提醒；如果用户之后主动重新开启，则按界面当前的“不终止”设置运行。

### 4.2 指定时间事件

#### 频率

- 使用下拉菜单。
- 选项为：
  1. 仅一次；
  2. 每天；
  3. 每周；
  4. 每月；
  5. 每年。
- 默认选择“仅一次”。

#### 指定时间

指定时间表单随频率变化：

| 频率 | 输入表单 | 初始化规则 |
| --- | --- | --- |
| 仅一次 | `YY年MM月DD日HH时MM分` | 选择该频率时，以当时的一小时之后初始化 |
| 每天 | `HH时MM分` | 选择该频率时，以当时的一小时之后初始化 |
| 每周 | 星期一下拉至星期日，再加 `HH时MM分` | 选择该频率时，以当时的一小时之后初始化星期和时间 |
| 每月 | `DD日HH时MM分` | 选择该频率时，以当时的一小时之后初始化日期和时间 |
| 每年 | `MM月DD日HH时MM分` | 选择该频率时，以当时的一小时之后初始化月份、日期和时间 |

“一小时之后”以用户切换或选择该频率的时刻为基点。

#### 终止次数

- 频率选择“仅一次”时，不显示终止次数设置；该事件按一次性计划自身的完成或错过规则关闭。
- 频率选择“每天”“每周”“每月”或“每年”时，显示与固定时间事件相同的终止次数下拉菜单并使用相同规则。
- 选项为“不终止、1 次、2 次、……、100 次”。
- 默认选择“不终止”。
- 选择有限次数时，界面显示剩余次数，并采用与固定时间事件相同的完成、跳过和延迟扣减规则。
- 到达终止条件后自动关闭事件。

## 5. 第二行第二列：息屏和锁屏策略

息屏和锁屏正式合并为一个模块，使用同一套共同设置，不分别保存两套策略。

### 5.1 固定时间事件

- 使用下拉菜单。
- 选项为：
  1. 继续计时；
  2. 重新计时；
  3. 暂停计时。
- 默认选择“暂停计时”。

选择“继续计时”后，额外显示一个条件选项：

- 息屏或锁屏期间发生事件时提醒；
- 息屏或锁屏期间发生事件时不提醒。

该附加选项默认选择“不提醒”。

### 5.2 指定时间事件

- 使用下拉菜单。
- 选项为：
  1. 提醒；
  2. 不提醒。
- “提醒”的含义是计划到点时发送普通通知。
- “不提醒”的含义是期间抑制普通通知，恢复后按既有规则提示“已跳过”。
- 默认选择“不提醒”。

### 5.3 实际睡眠或休眠

- 实际睡眠或休眠不放入这个可配置模块。
- 继续沿用固定规则：睡眠或休眠期间不发送提醒，唤醒后对期间到点事件提示“已跳过”。

## 6. 通知设置

### 6.1 自动消失时间

- 通知自动消失时间不再作为单条事件属性。
- 设置页面提供一个全局统一的自动消失时间。
- 默认值为 10 秒。
- 修改后对所有事件通知生效。
- 通知自行消失后按“延迟”处理，当前提醒在全局延迟时长结束后再次出现。

这条规则替代此前“每条事件可以设置不同自动消失时间”的需求。

Windows 当前原生通知 XML 的 `duration` 只提供 `short` 和 `long`，不直接接受任意秒数。精确控制为 10 秒或用户输入的其他秒数仍需在通知接口选型时验证实现方式。

### 6.2 延迟和通知操作

- 通知固定提供“完成”“延迟”“跳过本次”。
- 延迟时长也是全局设置，默认 5 分钟。
- 点击关闭叉号按“跳过本次”处理；通知自行消失按“延迟”处理。

### 6.3 通知颜色

- Windows 原生通知整体背景色和文字颜色由系统控制。
- Windows 11 仅为按钮提供绿色 `Success`、红色 `Critical` 两种语义样式。
- 当前不增加任意“通知颜色”事件属性。

## 7. 开关、暂停与非活动视觉

- 开关状态与暂停状态是两个字段。
- 暂停或关闭的事件均属于非活动状态，事件卡片整体显示得更淡。
- 开启切换为关闭时复用暂停逻辑。
- 关闭直接切换为开启时同时恢复。
- 编辑一个关闭事件并保存时，仍沿用既有规则：事件自动开启，但保留原有暂停属性。

## 8. 全局事件操作

### 8.1 全部暂停

- 对固定时间事件和指定时间事件全部生效。
- 固定时间事件冻结当前剩余时间。
- 指定时间事件在暂停期间到点时记为“已跳过”。

### 8.2 全部恢复

- 恢复全部暂停的事件。
- 固定时间事件继续暂停前的剩余时间。
- 指定时间事件继续原有日历计划，并按规则处理暂停期间错过的提醒。

### 8.3 全部重启

- 只对已经开始计时的固定时间事件生效。
- 每个符合条件的事件都清除本轮已经经过的时间，从完整间隔重新开始倒计时。
- 指定时间事件不受影响。

## 9. 当前事件卡片字段总表

| 行 | 顺序 | 模块 | 固定时间事件 | 指定时间事件 |
| --- | --- | --- | --- | --- |
| 第一行 | 1 | 名称 | 文本框 | 文本框 |
| 第一行 | 2 | 暂停/恢复 | 可用 | 可用 |
| 第一行 | 3 | 重启 | 可用，但仅限已开始计时 | 置灰且不可点击 |
| 第一行 | 4 | 倒计时 | 距离下一轮间隔 | 距离下一次有效计划 |
| 第一行 | 5 | 开关 | 默认开启 | 默认开启 |
| 第一行 | 6 | 删除 | 可用 | 可用 |
| 第二行 | 1 | 事件类型和时间 | 分钟间隔、终止次数 | 频率、指定时间；非“仅一次”时显示终止次数 |
| 第二行 | 2 | 息屏和锁屏 | 继续、重新、暂停；继续时再选是否提醒 | 提醒、不提醒 |

第一行一共六列。此前从第四列跳到第七列只是编号疏忽，原先称为第七列的开关实际是第五列，删除为第六列，不存在两项遗漏功能。

## 10. 当前已闭环事项与后续 UI 细节

以下事项已经闭环：

- 不再设置截止时间，只使用终止次数；
- 终止次数只在完成或跳过后扣减，延迟不扣；
- 次数减到 0 后自动关闭并显示“不终止”；
- 息屏和锁屏共用一套设置；
- 指定时间事件的重启按钮置灰；
- 指定时间默认“仅一次”，系统状态默认“不提醒”；
- 指定时间选择“仅一次”时隐藏终止次数设置；
- 通知自动消失走延迟逻辑，点击关闭叉号走跳过逻辑；
- 纯信息“已跳过”汇总会按其中列出的不同事件分别扣减终止次数；
- 所有自定义输入表单在保存或参与计算前都要通过合法性检查；
- 第一行确定为六列；
- 两个初始示例保持默认关闭。

后续仍可继续讨论：

1. “喝水”和“休息眼睛”两个初始示例各自的预设参数；
2. 各列的最终宽度、间距和横向滚动范围；
3. 当前视觉方向下各控件的最终尺寸、颜色值、圆角、边框、图标和过渡时间；
4. 事件名称、提醒间隔、日期与时间等字段的具体格式、长度和数值范围，以及校验失败时的界面提示方式。
5. 事件搜索输入框的搜索范围、匹配规则、无结果状态和结果定位方式。
