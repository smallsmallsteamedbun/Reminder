# Reminder 单条事件表单设计

- 文档状态：持续讨论与迭代
- 最近更新：2026-07-24
- 关联主文档：`docs/REQUIREMENTS.md`
- 关联逻辑细节：`docs/REMINDER_LOGIC_DETAILS.md`

本文档记录单条事件的界面结构、字段、默认值、动态表单、运行状态和操作逻辑。本文优先采用最近一次确认；尚不能由现有规则唯一确定的内容集中列在第 10 节，不在正文中擅自补全。

## 1. 事件列表和卡片结构

- 主页面采用顶部结构，不使用占用较多横向空间的宽侧边栏。
- 顶部左侧显示程序图标和名称，版本号放在图标旁或名称旁；顶部还可容纳设置入口和窗口控制。下方显示页面标题、“添加事件”和全局暂停、恢复、重启操作；主体显示事件卡片列表。
- 整体以 Windows 的按钮交互、焦点和状态反馈为基础，但不完全复刻 Windows。
- 当前自定义视觉方向使用冷灰底色、低饱和靛蓝主色和有轻微层次差异的卡片表面。
- `0.0.0` 初步简易版本只实现这一方向的单一浅色主题，不显示尚未实现的主题切换入口。
- 事件在列表中一条一条显示。
- 事件列表支持使用鼠标滚轮上下滚动；鼠标位于单条事件的横向滚动区域上时，滚轮仍用于纵向移动事件列表。
- 单条事件的横向滚动区域支持触摸板横向手势和系统横向滚轮消息；也可以使用 Shift 加鼠标滚轮横向移动。
- 终止次数和其他下拉菜单在收起时支持滚轮直接切换选项；展开后，鼠标位于弹出列表内时滚轮只滚动选项列表，不应被外层事件列表抢占。
- 展开的下拉菜单不应在主页滚动时悬浮在原位置；用户把鼠标移到主页滚动时，先收起当前下拉菜单，再滚动主页。
- 鼠标滚轮采用带自然启动和减速的平滑滚动，不直接跳变纵向位置。
- 所有列表与卡片动画都应按需短暂运行，优先采用不会逐帧触发布局重算的方式；动画结束后不得继续占用刷新计时。
- 每条事件是一个独立的带底框区域，使不同事件呈现为一栏一栏的卡片。
- 单条事件内部字段横向排列。
- 为避免非全屏窗口横向空间不足，每条事件允许横向滚动查看；拖动横向滚动条只是其中一种入口，不能作为唯一操作方式。
- 默认窗口大小和系统默认缩放比例下，全部事件字段应直接显示完整，不需要先横向移动；横向滚动继续保留以适配更小窗口和其他缩放比例。
- 动态表单的各功能位置按照该位置可能出现的最大内容预留空间，切换类型或频率时后续模块保持稳定。
- 每条事件分成上下两行，降低单行长度和拥挤程度。
- 暂停或关闭的非活动事件整体显示得更淡；活动事件保持正常显示强度，名称下方的“运行中”使用亮浅绿色。
- 主页面底部删除后台运行提示文字，只保留较薄的分隔边框。

## 2. 添加事件和内部身份

- 用户点击“添加事件”后，列表立即新增一条使用默认属性的事件。
- 如果新事件位于当前可见范围之外，列表自动滚动到该事件；新事件卡片的底框短暂高亮，帮助用户确认新增位置。
- 自动定位采用平滑滑动；滑动到目标位置后再开始卡片高亮。
- 每条事件具有一个不向用户显示的内部 `event id`。
- 保存、修改、删除和调度都使用 `event id` 识别事件，不用名称识别。
- 事件名称允许重名。

目前已经确认的新建自定义事件默认值：

| 属性 | 默认值 |
| --- | --- |
| 事件名称 | `新建事件` |
| 暂停状态 | 不暂停 |
| 暂停/恢复按钮文字 | `暂停` |
| 事件类型 | 固定时间事件 |
| 固定提醒间隔 | 45 分钟 |
| 终止次数 | 不终止 |
| 开启/关闭 | 开启 |

首次安装时提供的“喝水”和“休息眼睛”示例事件继续默认关闭。它们的具体预设参数以后再讨论；“新建自定义事件默认开启”不改变这两个初始示例。

### 2.1 通用输入校验

- 单条事件中所有允许用户自行填写的表单都必须检查输入是否合法。
- 输入必须在保存或参与提醒计算前通过校验；校验失败时不得应用本次输入。
- 非法格式、异常长度或过大数值不得导致数值溢出、程序崩溃或事件进入错误状态。
- 本要求适用于事件名称、固定提醒间隔、日期与时间等自定义输入字段。
- 事件名称最多 50 个加权字符：ASCII 字符权重为 1，中文等非 ASCII 字符权重为 2，因此最多 25 个中文字符或 50 个英文字符。
- 事件名称达到加权上限后，继续输入会被直接阻止，不先接收超限内容再显示长度错误。
- 日期与时间拆分字段分别校验；小时范围为 `0–23`，分钟范围为 `0–59`，分钟输入 `0` 和 `00` 都合法，保存后可以规范化显示为两位。
- 用户首次进入任一文本输入框时，光标默认放在已有内容末尾。

## 3. 第一行：名称、状态、操作和倒计时

第一行按当前描述依次包含以下功能块。

### 3.1 事件名称

- 第一列。
- 使用文本框。
- 用户点击文本框即可直接修改。
- 默认文字为“新建事件”。
- 最大长度采用 50 个加权字符；名称框不继续无意义占满卡片剩余空间，但在默认窗口和默认缩放下应完整显示达到上限的常见英文、中文或混合名称。
- 超过最大加权长度的后续输入直接被文本框拒绝，不显示长度超限提示。

### 3.2 暂停/恢复

- 第二列，仅固定时间事件显示。
- 使用一个根据状态切换文字的按钮。
- 事件正在运行时显示“暂停”。
- 点击“暂停”后事件暂停，按钮文字切换为“恢复”。
- 点击“恢复”后事件恢复，按钮文字切换为“暂停”。
- 新建事件默认不暂停，因此默认显示“暂停”。
- 指定时间事件不显示单项暂停/恢复按钮；其单项停止和恢复统一使用开启/关闭开关。

### 3.3 重启

- 第三列，仅固定时间事件显示。
- 按钮文字固定为“重启”。
- 对符合条件的固定时间事件，点击后清除当前一轮已经经过的时间，从完整的提醒时间间隔重新开始倒计时。
- 指定时间事件不能重启，也不显示“重启”按钮。

### 3.4 倒计时

- 第四列。
- 只读，用户不能修改。
- 表示距离该事件下一次提醒还有多久。
- 所有仍有未来提醒的事件都显示倒计时，包括固定时间事件和指定时间事件。
- 指定时间事件关闭但仍存在未来计划时，标题改为“距离下次发生但不提醒”，倒计时继续显示该计划距离现在的时间。
- 显示精度为秒，替代此前精确到分钟的旧想法。

显示规则：

1. 大于或等于 1 天：`DD天HH时MM分SS秒`；
2. 大于或等于 1 小时且小于 1 天：`HH时MM分SS秒`；
3. 小于 1 小时：`MM分SS秒`；
4. 天数不设显示上限，例如半年可以显示为 `183天……`。

已经失效、未来不会再发生的事件：

- 通常不显示倒计时；
- 每次程序启动时为每条失效事件随机计算一次；
- 有 5% 概率在倒计时位置显示彩蛋文字“弹一万遍反方向的钟”；
- 本次启动期间保持该次计算结果，下次启动重新计算。

### 3.5 开启/关闭

- 第五列。
- 使用开启/关闭滑块。
- 滑块切换时使用短暂、流畅且按需运行的位移动画；系统关闭界面动画时直接完成切换。
- 新建自定义事件默认选择开启。
- 切换为关闭时复用单项暂停逻辑。
- 固定时间事件从关闭直接切换为开启时保留已有暂停状态；如果仍暂停，用户通过“恢复”按钮继续。
- 指定时间事件的关闭与单项暂停语义合并，从关闭切换为开启时恢复日历调度。
- 成功修改事件其他设置时，事件自动开启并取消单项暂停，按照修改后的设置继续运行。

### 3.6 删除

- 第六列。
- 使用红色填充和红色边框。
- 点击后弹出“是否删除事件”确认框，提供“确定”和“取消”；确认按钮同样采用红色填充和红色边框。
- 只有点击“确定”才删除当前事件，点击“取消”保持事件不变。
- 点击“确定”并删除后，位于该事件下方的卡片通过平滑上移动画填补空位，不直接跳变位置。
- 初始示例事件和自定义事件都允许删除。

## 4. 第二行第一列：事件类型和时间设置

该区域先固定显示一个事件类型分段选择器：

- 左侧：固定时间事件；
- 右侧：指定时间事件；
- 默认停在左侧“固定时间事件”；
- 两个名称分别位于两个等宽区域内，当前选中的一侧显示底色，未选中的一侧保持透明或使用容器底色；
- 不使用普通开关轨道和圆形开关滑块的外观；
- 滑块下方的表单根据所选事件类型动态变化。

### 4.1 固定时间事件

#### 提醒时间间隔

- 使用输入框。
- 单位固定为分钟。
- 默认值为 45 分钟。

#### 终止次数

- 表示再提醒多少次后自动关闭事件。
- 使用下拉菜单。
- 选项为：
  - 不终止；
  - 1 次；
  - 2 次；
  - 依次增加；
  - 100 次。
- 最大值为 100 次。
- 默认选择“不终止”。
- 鼠标位于收起的终止次数下拉框内时，滚轮直接切换选项并阻止外层事件列表滚动。
- 终止次数下拉框展开后，鼠标位于弹出列表内时，滚轮只移动弹出列表的滚动位置，不直接修改当前选择，也不滚动主页。
- 选择有限次数时，界面显示剩余次数。
- 只有当前普通提醒最终被“完成”或“跳过本次”时才扣减 1 次。
- 点击“延迟”不扣减；延迟后再次出现仍是同一次提醒，最终完成或跳过时总共只扣减 1 次。
- 点击通知关闭叉号属于“跳过本次”，因此扣减 1 次；通知自行消失属于“延迟”，自动消失时不扣减。
- 恢复时显示的纯信息“已跳过”汇总也扣减终止次数：汇总中每个不同事件分别扣减 1 次，同一事件在同一段不可提醒状态中错过多次只汇总并扣减 1 次。
- 有限次数减到 0 后，事件自动关闭；由于下拉菜单没有“0 次”，关闭后该字段显示“不终止”。
- 事件已经关闭，因此显示“不终止”不会继续触发提醒；如果用户之后主动重新开启，则按界面当前的“不终止”设置运行。

### 4.2 指定时间事件

#### 频率

- 使用下拉菜单。
- 选项为：
  1. 仅一次；
  2. 每天；
  3. 每周；
  4. 每月；
  5. 每年。
- 默认选择“仅一次”。

#### 指定时间

指定时间表单随频率变化：

| 频率 | 输入表单 | 初始化规则 |
| --- | --- | --- |
| 仅一次 | 独立的年、月、日、时、分输入框 | 选择该频率时，以当时的一小时之后初始化 |
| 每天 | 独立的时、分输入框 | 选择该频率时，以当时的一小时之后初始化 |
| 每周 | 星期一下拉至星期日，再加独立的时、分输入框 | 选择该频率时，以当时的一小时之后初始化星期和时间 |
| 每月 | 独立的日、时、分输入框 | 选择该频率时，以当时的一小时之后初始化日期和时间 |
| 每年 | 独立的月、日、时、分输入框 | 选择该频率时，以当时的一小时之后初始化月份、日期和时间 |

“一小时之后”以用户切换或选择该频率的时刻为基点。

每个数值输入框后显示对应的“年、月、日、时、分”单位。日期组合必须真实存在；小时允许 `0–23`，分钟允许 `0–59`，`0` 与 `00` 都是合法分钟输入。

#### 终止次数

- 频率选择“仅一次”时，不显示终止次数设置；该事件按一次性计划自身的完成或错过规则关闭。
- 频率选择“每天”“每周”“每月”或“每年”时，显示与固定时间事件相同的终止次数下拉菜单并使用相同规则。
- 选项为“不终止、1 次、2 次、……、100 次”。
- 默认选择“不终止”。
- 选择有限次数时，界面显示剩余次数，并采用与固定时间事件相同的完成、跳过和延迟扣减规则。
- 到达终止条件后自动关闭事件。

## 5. 第二行第二列：息屏和锁屏策略

息屏和锁屏正式合并为一个模块，使用同一套共同设置，不分别保存两套策略。

### 5.1 固定时间事件

- 使用下拉菜单。
- 选项为：
  1. 继续计时；
  2. 重新计时；
  3. 暂停计时。
- 默认选择“暂停计时”。

选择“继续计时”后，额外显示一个条件选项：

- 息屏或锁屏期间发生事件时提醒；
- 息屏或锁屏期间发生事件时不提醒。

该附加选项默认选择“不提醒”。

### 5.2 指定时间事件

- 使用下拉菜单。
- 选项为：
  1. 提醒；
  2. 不提醒。
- “提醒”的含义是计划到点时发送普通通知。
- “不提醒”的含义是期间抑制普通通知，恢复后按既有规则提示“已跳过”。
- 默认选择“不提醒”。

### 5.3 实际睡眠或休眠

- 实际睡眠或休眠不放入这个可配置模块。
- 继续沿用固定规则：睡眠或休眠期间不发送提醒，唤醒后对期间到点事件提示“已跳过”。

## 6. 通知设置

### 6.1 自动消失时间

- 通知自动消失时间不再作为单条事件属性。
- 设置页面提供一个全局统一的自动消失时间。
- 默认值为 10 秒。
- 修改后对所有事件通知生效。
- 通知自行消失后按“延迟”处理，当前提醒在全局延迟时长结束后再次出现。

这条规则替代此前“每条事件可以设置不同自动消失时间”的需求。

Windows 当前原生通知 XML 的 `duration` 只提供 `short` 和 `long`，不直接接受任意秒数。精确控制为 10 秒或用户输入的其他秒数仍需在通知接口选型时验证实现方式。

### 6.2 延迟和通知操作

- 通知固定提供“完成”“延迟”“跳过本次”。
- 延迟时长也是全局设置，默认 5 分钟。
- 点击关闭叉号按“跳过本次”处理；通知自行消失按“延迟”处理。

### 6.3 通知颜色

- Windows 原生通知整体背景色和文字颜色由系统控制。
- Windows 11 仅为按钮提供绿色 `Success`、红色 `Critical` 两种语义样式。
- 当前不增加任意“通知颜色”事件属性。

## 7. 开关、暂停与非活动视觉

- 开关状态与暂停状态是两个字段。
- 暂停或关闭的事件均属于非活动状态，事件卡片整体显示得更淡。
- 开启切换为关闭时复用暂停逻辑。
- 固定时间事件处于关闭且暂停时，直接开启仍保留暂停，之后可点击“恢复”继续。
- 指定时间事件不提供单项暂停按钮，开启和关闭直接控制其单项日历调度。
- 编辑任一事件并成功保存设置时，事件自动开启并取消单项暂停。

## 8. 全局事件操作

### 8.1 全部暂停

- 对固定时间事件和指定时间事件全部生效。
- 固定时间事件冻结当前剩余时间。
- 指定时间事件在暂停期间到点时记为“已跳过”。

### 8.2 全部恢复

- 恢复全部暂停的事件。
- 固定时间事件继续暂停前的剩余时间。
- 指定时间事件继续原有日历计划，并按规则处理暂停期间错过的提醒。

### 8.3 全部重启

- 只对已经开始计时的固定时间事件生效。
- 每个符合条件的事件都清除本轮已经经过的时间，从完整间隔重新开始倒计时。
- 指定时间事件不受影响。

## 9. 当前事件卡片字段总表

| 行 | 顺序 | 模块 | 固定时间事件 | 指定时间事件 |
| --- | --- | --- | --- | --- |
| 第一行 | 1 | 名称 | 文本框 | 文本框 |
| 第一行 | 2 | 暂停/恢复 | 可用 | 不显示 |
| 第一行 | 3 | 重启 | 可用，但仅限已开始计时 | 不显示 |
| 第一行 | 4 | 倒计时 | 距离下一轮间隔 | 开启时距离下次提醒；关闭时距离下次发生但不提醒 |
| 第一行 | 5 | 开关 | 默认开启 | 默认开启 |
| 第一行 | 6 | 删除 | 可用 | 可用 |
| 第二行 | 1 | 事件类型和时间 | 分钟间隔、终止次数 | 频率、指定时间；非“仅一次”时显示终止次数 |
| 第二行 | 2 | 息屏和锁屏 | 继续、重新、暂停；继续时再选是否提醒 | 提醒、不提醒 |

固定时间事件第一行使用六个功能位置。指定时间事件不显示暂停/恢复和重启，倒计时利用空出的区域，但开关和删除仍保持稳定位置。

## 10. 当前已闭环事项与后续 UI 细节

以下事项已经闭环：

- 不再设置截止时间，只使用终止次数；
- 终止次数只在完成或跳过后扣减，延迟不扣；
- 次数减到 0 后自动关闭并显示“不终止”；
- 息屏和锁屏共用一套设置；
- 指定时间事件不显示重启按钮；
- 指定时间默认“仅一次”，系统状态默认“不提醒”；
- 指定时间选择“仅一次”时隐藏终止次数设置；
- 通知自动消失走延迟逻辑，点击关闭叉号走跳过逻辑；
- 纯信息“已跳过”汇总会按其中列出的不同事件分别扣减终止次数；
- 所有自定义输入表单在保存或参与计算前都要通过合法性检查；
- 第一行确定为六列；
- 两个初始示例保持默认关闭。

后续仍可继续讨论：

1. “喝水”和“休息眼睛”两个初始示例各自的预设参数；
2. 各列的最终宽度、间距和横向滚动范围；
3. 当前视觉方向下各控件的最终尺寸、颜色值、圆角、边框、图标和过渡时间；
4. 提醒间隔等仍未逐项确定的字段范围，以及各类校验失败提示的最终文案。
5. 事件搜索输入框的搜索范围、匹配规则、无结果状态和结果定位方式。
