# Reminder 下一阶段：主页与多页面导航实施计划

- 确认日期：2026-07-27，2026-07-28 补充渲染模式设置
- 基线版本：`0.4.1`
- 计划状态：已实施并完成首轮回归与资源验证
- 关联需求：`docs/REQUIREMENTS.md`
- 主页设计：`docs/HOME_PAGE_DESIGN.md`
- 设置页设计：`docs/SETTINGS_PAGE_DESIGN.md`

## 1. 阶段目标

本阶段把当前单一事件列表界面扩展为“主页、事件、设置”三个顶级页面，并完整实现已经确认的主页查看与定位闭环。

本阶段完成后：

- 主页能够清楚展示最近提醒和当前倒计时；
- 当前事件列表成为独立事件页，原有编辑和交互能力不回退；
- 用户可以从主页目标事件直接进入事件页并定位、高亮；
- 设置页具有正式页面容器、导航入口和切换能力，并完整提供渲染模式设置、保存、重启提示和立即或稍后生效逻辑；
- 主页继续只读映射现有提醒状态，不增加第二套事件、计时器或调度状态。
- 软件渲染和硬件优先渲染都完成主页显示、动画及可见与隐藏资源占用验证。

## 2. 已确认实施范围

### 2.1 多页面外壳

- 建立“主页、事件、设置”三个顶部导航入口。
- 顶部品牌区域继续显示程序图标、名称、版本号和标语，导航保持在窗口视觉中心。
- 建立统一页面容器和可取消的页面切换状态。
- 主页和事件页共用全部暂停/全部恢复与全部重启；事件页额外显示添加事件。
- 设置页不显示提醒全局操作。

### 2.2 事件页迁移

- 将当前事件列表完整迁入事件页，不重写已经稳定的提醒业务逻辑。
- 保留事件编辑、滚轮与触摸板滚动、展开下拉列表、新建定位、删除确认、删除重排、高亮和横向滚动。
- 通过顶部导航进入事件页时保留上一次滚动位置。
- 从主页进入具体事件时，用目标事件定位覆盖原滚动位置，并复用现有短暂高亮效果。

### 2.3 主页只读状态映射

- 主页从现有事件快照和全部暂停快照生成展示数据，不直接修改提醒状态。
- 按剩余时间和事件列表顺序稳定筛选最多三个最近事件。
- 排除关闭和用户单项暂停的事件。
- 正确映射普通运行、全部暂停、等待通知处理、暂停期间已经发生和无运行事件等状态。
- 全部暂停、全部恢复或其他业务操作改变事件状态后，重新计算主页候选、顺序和当前目标。

### 2.4 主圆形与最近事件卡片

- 实现固定位置的大型圆形主计时器，显示当前目标事件名称和自适应格式倒计时。
- 右侧按一张、两张或三张卡片使用固定槽位，并沿圆形右侧圆弧排列。
- 卡片显示事件名称和剩余时间；悬停卡片时，圆形临时切换到该事件。
- 点击卡片或圆形进入事件页并定位目标；无运行事件时点击空状态圆形只进入事件页。
- 卡片选择只改变底色、边框、阴影等反馈，不移动固定槽位。

### 2.5 多层倒计时圆环

- 从内向外绘制秒、分、时、天圆环，只显示当前分量的彩色弧线，不绘制完整背景轨道。
- 超过 365 天时只增加一个完整外环，中心仍显示真实总天数。
- 普通分量变化使用短时平滑过渡，回绕到接近满值时使用快速涨满。
- 悬停切换目标事件时，圆环组和圆形在动画峰值附近切换数据，不进行长距离追赶旋转。
- 只让实际发生变化的可见圆环执行动画；页面隐藏或动画完成后不保留渲染回调、动画时钟或额外刷新。

### 2.6 页面与内容变化动画

- 主页与事件页使用已经确认的事件列表整体拉入和拉走动画。
- 添加事件按钮按页面方向短距离移动并淡入或淡出，共用全局按钮保持原位。
- 主页与设置页使用更短的整体淡入淡出。
- 事件页与设置页按已确认方向散去或进入。
- 连续快速导航时以最后选择的页面为目标，不排队播放所有过渡。
- 最近事件变化时只强调实际变化的卡片槽位；圆形目标变化时使用轻微膨胀和数据切换。

### 2.7 设置页与渲染模式

- 创建设置页页面容器、顶部导航入口和页面切换动画。
- 实现“渲染模式”下拉框，选项严格为“软件渲染（兼容模式）”和“硬件优先渲染”，默认值为“硬件优先渲染”。
- 选择变化后立即保存设置，并显示“更改此设置软件需要重启”提示框。
- 提示框提供“立即重启软件”和“稍后自行重启”。
- “立即重启软件”复用统一状态保存和启动恢复边界，结束旧进程并启动应用新模式的新进程。
- “稍后自行重启”不改变当前进程实际模式；用户以后退出时保留新设置，并在下一次启动窗口前应用。
- 除渲染模式外，本阶段不创建其他设置条目、设置表单或设置业务逻辑。

## 3. 模块与资源边界

- `Logic` 继续提供唯一的事件状态、全部暂停状态和调度结果。
- `UI` 负责把现有快照投影为主页只读展示模型、管理页面导航和视觉动画。
- `UI` 负责展示渲染模式下拉框和重启提示，但不直接操作进程或持久化文件。
- `System` 负责保存渲染模式、协调立即重启，并保证稍后重启选择能够跨退出保留。
- 应用启动层必须在创建首个 WPF 窗口前读取渲染模式：软件模式映射为 `SoftwareOnly`，硬件优先模式恢复 WPF 默认渲染偏好。
- 主页不得建立独立业务计时器；界面可见时复用现有轻量逐秒刷新节奏，窗口隐藏后停止界面刷新。
- 主页、事件页和设置页的切换不改变事件业务状态。
- 持久化状态增加版本化渲染模式字段；旧状态缺少该字段时迁移为“硬件优先渲染”。不得把下拉框显示文字直接作为持久化业务值。
- 动画继续使用持续时间和实际经过时间，不固定帧数，并遵守 Windows 客户区动画设置。
- 软件渲染下的圆环和页面动画继续遵守局部重绘、短时按需和结束后清理的资源边界，避免大面积动态模糊、复杂透明蒙版和高成本阴影。

## 4. 建议实施顺序

### 阶段 A：只读投影与测试

- 建立主页候选、排序、当前目标和特殊状态的只读展示模型。
- 先用纯逻辑测试覆盖同剩余时间排序、候选排除、最多三项、全部暂停、等待处理和空状态。

### 阶段 B：页面外壳与事件页迁移

- 建立顶级导航和页面容器。
- 把现有事件列表移动到事件页，先保证原有交互零回退。
- 接通普通进入事件页和带目标事件进入事件页两种路径。

### 阶段 C：主页静态布局与交互

- 实现圆形、固定卡片槽位、事件名称和倒计时。
- 实现悬停切换、离开恢复、点击定位和无事件空状态。

### 阶段 D：圆环与状态变化

- 实现秒、分、时、天及超过 365 天外环。
- 接入全部暂停、等待处理和候选集合变化。
- 完成圆环数值变化和目标切换动画。

### 阶段 E：页面切换与渲染设置

- 实现主页、事件页和设置页之间的已确认过渡。
- 创建设置页容器和渲染模式下拉框。
- 扩展版本化状态，保存渲染模式并兼容旧状态默认值。
- 实现“立即重启软件”和“稍后自行重启”，验证重启前保存、旧进程退出、新进程等待和启动恢复。
- 保证渲染模式在首个 WPF 窗口创建前应用。
- 回归连续导航、中断动画、窗口隐藏和重新显示。

### 阶段 F：整体回归

- 检查事件页全部现有功能。
- 检查主页候选、排序、特殊状态、定位和全局操作。
- 检查常用窗口与最小窗口排版、中文显示和缩放。
- 检查动画结束后 CPU 回落，窗口隐藏后没有持续界面刷新。
- 在软件渲染和硬件优先渲染下分别测量主页静止、圆环更新、卡片悬停、页面切换和窗口隐藏场景的 CPU、工作集、私有内存和托管堆。
- 在本机 `2560×1600 / 120Hz` 环境验证软件渲染主页的流畅度，并在条件允许时补充其他显卡设备对照。
- 完成 Debug、Release、逻辑测试和界面渲染复核。

## 5. 本阶段明确不实现

- 设置页中除渲染模式以外的其他设置条目与业务逻辑；
- 主题切换；
- 开机自动启动和静默启动；
- 版本检查、`new` 标记、自动更新和更新失败页面；
- Inno Setup 安装、卸载和覆盖更新；
- 事件搜索；
- 新的提醒类型、循环频率或通知操作；
- 除新增渲染模式字段及其兼容迁移外的其他持久化结构升级。

## 6. 验收标准

- 三个顶级页面可以稳定切换，连续操作不会产生错页、动画排队或残留遮挡。
- 事件页原有功能和滚动位置保持正常。
- 主页最近事件的候选、顺序、圆形目标和特殊状态与逻辑层一致。
- 圆形、卡片和圆环在无事件、一至三项事件、长名称和长倒计时下均不发生乱码或明显错位。
- 从主页进入事件页能够准确定位并高亮目标事件。
- 全部暂停、全部恢复和全部重启后主页及时更新。
- 页面隐藏后停止无意义的逐秒视觉刷新和动画工作。
- 渲染模式下拉框默认值与两个选项正确，更改后提示文字和两个操作按钮与需求一致。
- “立即重启软件”能够保存并恢复当前状态，且新模式从新进程首个窗口开始生效。
- “稍后自行重启”不改变当前进程模式，退出后下一次启动仍应用新设置。
- 软件渲染下主页圆形、圆环、卡片和页面切换显示完整；资源测量结果被记录，并能在窗口隐藏后停止无意义的界面渲染。
- Debug 与 Release 构建保持零警告、零错误，既有提醒、持久化与系统状态回归不退化。
