# Reminder 下一阶段：数据持久化与生命周期闭环实施规划

- 规划日期：2026-07-27
- 规划状态：已确认，等待用户备份后授权实施
- 当前版本：`0.3.0`
- 本文性质：已确认需求对应的实施范围，不代表代码已经完成

## 1. 阶段目标

下一阶段实现到“用户配置一次后，可以长期保存、退出并恢复”的完整程度。

该阶段完成后，Reminder 应当能够：

1. 保存全部事件配置和恢复提醒所需的运行状态；
2. 从托盘执行真正退出；
3. 下次启动时先恢复已有状态，再启动提醒调度；
4. 正确处理软件离线期间发生的指定时间事件；
5. 正常退出时保存最新状态，异常退出时回退到最近一次低频快照；
6. 使用非明文、可校验、可迁移并且低磁盘活动的文件存储；
7. 把状态、备份和临时文件全部保存在软件自身目录的相对 `Data` 文件夹内；
8. 为以后 Inno Setup 覆盖更新保留不会被替换的稳定数据边界。

主页与多页面导航排在该阶段之后。主页只读取恢复后的逻辑状态，不参与持久化和调度。

## 2. 已确认的数据位置

所有路径以 Reminder 可执行程序的实际所在目录为基准，不使用进程当前工作目录。

```text
<Reminder 安装目录>\
├─ Reminder.exe
├─ 其他程序文件
├─ 卸载程序
└─ Data\
   ├─ state.dat
   ├─ state.bak
   ├─ state.tmp
   └─ Updates\
```

- `state.dat`：当前正式状态文件；
- `state.bak`：最近一份可恢复备份；
- `state.tmp`：完成原子替换前的临时文件；
- `Updates\`：以后软件内更新下载新版安装程序的位置。

Reminder 自身产生的配置、状态、备份和更新文件不写入 `%AppData%`、`%LocalAppData%` 或其他 C 盘位置。

## 3. 状态文件边界

持久化文件采用版本化 JSON 数据文档，经 UTF-8 序列化后再由 Windows DPAPI 使用当前用户范围整体保护，最终以非明文二进制保存。

状态文档至少承载：

- 独立的数据结构版本；
- 保存时刻和正常退出所需的时间边界；
- 事件顺序和每个事件的内部 ID；
- 事件名称、类型、计划配置和开关；
- 固定时间事件的单项暂停、当前剩余时间和系统状态策略；
- 指定时间事件的频率、日期时间字段和系统状态策略；
- 当前终止次数；
- 当前全部暂停方式和冻结后的剩余暂停时间；
- 等待恢复汇总的错过事件；
- 退出时尚未处理的普通通知所需的恢复结果；
- 后续已经确认的全局设置。

运行时模型不直接作为磁盘格式。`Logic` 提供明确的状态导出与导入边界，`System` 负责序列化、保护、文件替换和恢复；UI、Windows 回调和可视控件不得直接写状态文件。

## 4. 保存规则

### 4.1 主动退出

- 托盘菜单增加“退出”。
- 点击后先阻止新的用户操作，整理未处理通知和最终状态，再执行一次完整保存。
- 保存成功后依次释放托盘、Windows 状态监测、界面刷新、提醒调度和通知服务，最后显式关闭进程。
- 主窗口右上角关闭仍然只隐藏窗口，不触发完整退出。

### 4.2 低频保存

- 正常运行期间约每 1 小时保存一次，周期无需精确。
- 用户每次编辑、暂停、恢复、完成、延迟或跳过后不立即写盘。
- 同一时刻只允许一个保存操作；重复保存请求应合并，避免并发覆盖和多余磁盘活动。

### 4.3 Windows 正常结束

- Windows 正常关机或会话结束时尽力执行最终保存。
- 如果系统没有提供足够时间，则接受回退到最近一次低频快照，不增加高频保存。

### 4.4 原子写入

1. 生成一致的逻辑状态快照；
2. 序列化为带结构版本的 JSON 字节；
3. 使用 DPAPI 当前用户范围保护；
4. 完整写入 `state.tmp`；
5. 完成写入后原子替换 `state.dat`，并按最终恢复规则维护 `state.bak`；
6. 失败时不得用不完整临时文件覆盖可用正式状态。

## 5. 启动与离线恢复

启动顺序固定为：

1. 创建存储服务并查找 `Data\state.dat`；
2. 解密、检查完整性、验证结构版本和字段范围；
3. 将有效状态交给逻辑层恢复；
4. 没有有效存档时才创建默认关闭的“喝水”和“休息眼睛”示例；
5. 恢复完成后再接入 Windows 状态监测、最近到期调度、通知、托盘和界面。

具体恢复规则：

- 固定时间事件保存剩余时间，软件离线期间冻结，启动后从原剩余时间继续；
- 延迟后的固定剩余时间按普通剩余时间保存和恢复；
- 已暂停固定事件恢复后仍保持单项暂停；
- 限时全部暂停保存剩余暂停时间，离线期间冻结；
- 指定时间事件检查离线区间内是否发生计划，同一事件无论发生几次只进入一次“已跳过”汇总；
- 循环指定时间事件继续计算下一个未来计划；
- 一次性事件在恢复汇总后关闭并保留在列表；
- 退出时尚未处理的普通通知在下次真正恢复时纳入“已跳过”汇总；
- 真正恢复仍需满足程序运行、用户解锁、事件未单项暂停且全部暂停结束。

## 6. 数据拒绝与恢复

- 无法解密、DPAPI 完整性检查失败、JSON 无法解析、结构版本不受支持或字段校验失败的数据不得进入提醒逻辑。
- `state.dat` 加载失败时自动尝试从 `state.bak` 恢复，备份数据必须经过相同的解密、完整性、结构版本和字段校验。
- 如果 `state.bak` 也无法恢复，打开独立的恢复失败提示窗口；该窗口显示恢复失败并提供确认操作，用户确认后关闭提示窗口。
- 两份状态均无效时不得把其中任何部分交给提醒逻辑；提示关闭后按照无有效存档的启动流程继续。
- `state.bak` 的具体生成时机以及何时保留损坏文件，仍在实现时结合原子替换流程确定。
- 数据迁移必须按独立的数据结构版本进行，不能直接把应用版本号当作存储版本。
- DPAPI 当前用户保护意味着数据不能保证跨 Windows 用户、系统重装或不同电脑解密；相对 `Data` 目录便于整体备份，但不改变该保护边界。

## 7. 安装、更新与数据的边界

正式发布使用 Inno Setup 生成自包含 `.exe` 安装程序，不再采用 MSIX 或 Windows App Installer。

- 安装时允许用户选择包括 D 盘在内的目标目录；
- 安装程序创建相对 `Data` 目录和 Windows 卸载入口；
- 受保护安装位置只给 `Data` 子目录必要写权限，不开放程序目录写权限；
- 软件内更新模块下载并校验新版安装程序；
- 用户确认后，Reminder 保存状态、退出，并由 Inno Setup 静默覆盖原安装目录；
- 覆盖更新只替换程序文件，保留 `Data`，完成后重新启动 Reminder；
- 卸载开始前必须询问用户选择“保留 Data”或“删除 Data”：选择保留时不处理 `Data`，选择删除时移除整个 `Data` 目录。

安装器和自动更新功能本身不在本持久化阶段实现；本阶段只保证数据位置和生命周期不会阻碍以后覆盖更新。

## 8. 内部实施顺序

### 阶段 A：建立稳定状态合同

1. 定义独立的存储文档和结构版本；
2. 为 Logic 增加只读导出快照和受校验导入入口；
3. 覆盖固定计划、指定计划、终止次数、事件策略、暂停和错过集合；
4. 保证导入失败不会留下半恢复状态。

### 阶段 B：实现受保护文件存储

1. 在 `System` 模块实现相对 `Data` 路径服务；
2. 实现 JSON 序列化、DPAPI 保护和解密；
3. 实现临时文件、原子替换和备份；
4. 实现单写入串行化和约一小时低频保存。

### 阶段 C：接入应用生命周期

1. 启动时先加载状态，没有存档时才初始化示例事件；
2. 接入托盘“退出”和显式关闭；
3. 接入 Windows 正常会话结束保存；
4. 闭环未处理通知、限时暂停和离线指定时间事件。

### 阶段 D：恢复与回归验证

1. 覆盖正常退出、再次启动和多次覆盖保存；
2. 覆盖固定事件、延迟、单项暂停和全部暂停恢复；
3. 覆盖一次性与循环指定时间事件的离线错过；
4. 覆盖损坏、篡改、截断、旧结构和备份回退；
5. 验证保存期间崩溃不会破坏最后可用状态；
6. 检查后台磁盘活动、内存、CPU、计时器和事件订阅；
7. 完成 Debug、Release、逻辑、界面和真实退出回归。

## 9. 验收标准

- 第一次启动创建默认示例，第二次启动不重复创建；
- 用户编辑、暂停和计时状态在主动退出后完整恢复；
- 软件离线时固定剩余时间和限时全部暂停均不流逝；
- 离线指定时间计划按既有规则汇总，循环与一次性行为正确；
- 退出时未处理通知在下次恢复时只汇总一次；
- 损坏或篡改数据不会使程序崩溃，也不会进入调度；
- `state.dat` 无法载入时会自动回退到有效的 `state.bak`；两者均无效时只显示一次可确认关闭的恢复失败窗口；
- 写入中断后仍至少保留一份可用状态；
- 主窗口关闭继续后台运行，只有托盘“退出”真正结束进程；
- 所有运行数据都位于相对 `Data` 目录；
- 空闲时不增加高频轮询或频繁磁盘写入；
- Debug 和 Release 构建零错误、零警告，界面无乱码和明显错位。

## 10. 本阶段明确不做

- 主页和三页面导航的实际代码；
- 事件搜索；
- 独立设置页面；
- 主题切换；
- 开机启动和静默启动；
- 版本联网检查和 `new` 标记；
- Inno Setup 安装包、软件内更新下载和正式发布；
- 自动删除或迁移尚未确认的旧数据。
