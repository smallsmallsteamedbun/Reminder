# Reminder 主页与多页面导航设计

- 文档状态：首轮设计已实施并完成初步功能、界面与资源验证
- 最近更新：2026-07-28
- 关联主文档：`docs/REQUIREMENTS.md`
- 关联事件页设计：`docs/EVENT_FORM_DESIGN.md`
- 关联设置页设计：`docs/SETTINGS_PAGE_DESIGN.md`
- 关联实施计划：`docs/NEXT_STAGE_HOME_NAVIGATION_PLAN.md`

本文档记录主页、事件页、设置页的页面关系、主页计时器、最近事件卡片和页面切换交互。正文只采用已经确认的内容；仍与既有调度规则存在展示边界，或尚未确定精确参数的事项集中列在第 11 节。

## 1. 顶级页面与顶部结构

- 当前顶级页面为“主页”“事件”“设置”，不为尚未确认的功能增加更多顶级选项卡。
- 关于软件、版本更新和主题等全局内容归入设置或现有品牌区域；通知历史继续由 Windows 通知中心承担，不新增独立的历史或统计页面。
- 页面顶部第一层左侧显示程序图标、名称、版本号和标语；“主页”“事件”“设置”导航位于窗口的视觉中心。
- 顶部导航左右使用平衡布局，使导航不因左侧品牌区域宽度而偏离窗口中心。
- 页面顶部第二层作为页面操作区，不再显示“提醒事件”大标题。
- 主页和事件页共用“全部暂停/全部恢复”和“全部重启”；事件页额外显示“添加事件”。
- 事件页可以在操作区左侧用较弱的文字显示事件总数和运行中数量，不再使用重复的大标题。
- 设置页不显示上述提醒全局操作。
- 当前确认的首轮实施除建立设置页容器、导航入口和切换动画外，还要完整实现渲染模式设置、持久化、重启提示和立即或稍后生效逻辑；其他设置条目暂不实现。

## 2. 主页主体构图

- 主页主体由一个固定位置的大型圆形主计时器和右侧最近事件卡片区域组成。
- 圆形的位置始终固定，不因候选事件数量或悬停目标变化而移动。
- 右侧卡片区域也使用固定布局；分别为一张、两张或三张卡片定义稳定位置，事件数量变化时不重新居中整个组合。
- 一张卡片时使用中间槽位；两张卡片时使用上下对称槽位；三张卡片时使用上、中、下三个槽位。
- 右侧最多展示三个最近发生的正在计时事件：
  - 只有一个候选事件时显示一张卡片；
  - 有两个候选事件时显示两张卡片；
  - 有三个或更多候选事件时只显示前三张。
- 卡片使用能够容纳较长事件名称的长方形，而不是严格正方形。
- 三个卡片不采用相同横坐标垂直对齐，而是贴合左侧圆形的右侧圆弧排列：中间卡片比上、下卡片更向右突出约 28–36 像素。

## 3. 最近事件候选与排序

- 主页只读取提醒逻辑层已经存在的事件状态并形成展示映射，不为主页建立另一套事件、调度器、计时状态或可修改的业务数据。
- 主页最近事件以仍在参与提醒计时的事件为候选。
- 用户手动单项暂停的固定时间事件从主页最近事件候选中排除。
- 已关闭事件不作为正在计时事件展示。
- 候选事件首先按当前剩余时间从短到长排序。
- 多个事件剩余时间相同时，事件列表中位置更靠上的事件优先，保证展示顺序唯一且稳定。
- 鼠标不在任何右侧卡片内时，圆形默认显示排序第一的最近事件。
- 执行全部暂停或全部恢复后，候选集合和顺序必须依据最新事件状态重新计算。
- 全部暂停期间主页不清空，而是继续保留暂停事件及其状态：
  - 固定时间间隔事件显示进入暂停后冻结的剩余时间；
  - 指定时间事件继续显示距离真实计划时刻的时间，卡片变淡并显示“暂停中，到点不提醒”；
  - 指定时间已经在暂停期间发生后，显示“暂停期间已发生”，直到恢复时按既有规则进入“已跳过”汇总。
- 已经到点并等待用户在 Windows 通知中处理的普通提醒保持主页最高展示优先级，圆形和对应卡片显示“等待处理”；主页不增加完成、延迟或跳过按钮。

## 4. 圆形主计时器

- 圆形内部同时显示当前目标事件的名称和剩余时间。
- 倒计时使用适应剩余时长的格式：
  - 小于一小时：以分钟和秒为主要内容；
  - 小于一天且大于或等于一小时：显示时、分、秒；
  - 大于或等于一天：以总天数为主要内容，并辅助显示时、分、秒。
- 长事件名称允许使用有限行数展示，超出空间时省略，不能挤压或推动圆形位置。
- 圆形可以点击。点击后进入事件页，定位到当前圆形正在展示的事件，并使用与新增事件定位相同的短暂高亮提示。
- 没有任何正在计时事件时仍保留圆形位置，中心显示“暂无正在计时的事件”；右侧不显示事件卡片，圆形周围不显示空圆环轨道。点击该空状态圆形进入事件页，但不定位具体事件。

## 5. 多层倒计时圆环

- 圆形周围使用多层圆环表达当前事件剩余时间的不同分量，不表示事件完整周期的完成百分比。
- 圆环不绘制较淡的完整背景轨道，只绘制代表当前时间分量的彩色部分；分量为零或处于无倒计时状态时，对应彩色圆环不显示。
- 所有圆环从正上方十二点方向开始，按顺时针方向绘制，彩色弧线端点采用圆头，并在相邻圆环之间保留清楚间距。
- 圆环从内向外依次为：
  1. 秒环：60 秒一圈；
  2. 分环：60 分钟一圈；
  3. 时环：24 小时一圈；
  4. 天环：365 天一圈。
- 天环不区分平年和闰年的 365 天与 366 天差异。
- 倒计时超过 365 天时：
  - 天环使用总天数除以 365 后的余数；
  - 天环外侧只增加一个完整圆环表示“超过 365 天”，不随完整年份数量继续增加更多圆环；
  - 圆形中心文字仍显示真实总天数。
- 倒计时回到 365 天时，额外圆环消失，基础天环显示完整一圈；继续减少后按 `当前天数 ÷ 365` 显示。
- 各圆环与圆形内当前展示事件的倒计时同步。例如剩余 `180天20小时1分钟59秒` 时：
  - 秒环接近满；
  - 分环只有少量；
  - 时环接近满；
  - 天环约为一半。
- 时间分量每次减少时，对应圆环从上一个位置快速过渡到新位置，过渡包含自然的加速和减速。
- 秒、分、时、天分量从零回到下一周期的接近满值时，对应圆环使用约 1 秒的回弹动画。
- 圆环采用以下初步确认配色，并在深色主题下保持色相、适当提高亮度：
  - 秒环：薄荷青 `#67D2C4`；
  - 分环：柔和蓝 `#61A6E8`；
  - 时环：低饱和靛蓝 `#7B82E6`；
  - 天环：淡紫 `#A581D8`；
  - 超过 365 天的完整外环：柔和金色 `#D8B56A`。
- 普通数值减少时，对应圆环建议在约 180–240 毫秒内完成过渡；从零恢复到下一周期时，不经过真正的完整满圈，而是用约 1 秒回弹到该周期“差一点满”的实际目标值，例如秒环回到 `59/60`。
- 只有实际变化的圆环执行动画：秒环每秒短暂变化，分、时、天环只在各自分量变化时运行；动画结束后不保留持续渲染。
- 用户悬停切换圆形目标事件时，不让各圆环以倒计时方式长距离旋转到新数值；整个圆环组随圆形轻微膨胀，在动画顶点切换并交叉淡入新数据。

## 6. 右侧事件卡片交互

- 每张卡片显示事件名称和剩余时间。
- 鼠标进入某张卡片后，圆形改为显示该事件的名称、倒计时和圆环状态。
- 鼠标离开整个卡片区域后，圆形恢复显示排序第一的最近事件。
- 被指向的卡片通过底色、边框、轻量阴影和短距离抬升呈现“被选中”与漂浮的感觉；抬升不改变所属固定槽位，卡片不跟随鼠标移动。
- 卡片静止时也通过层次、留白和轻量静态阴影形成漂浮感，不持续执行上下漂移动画。
- 点击卡片后进入事件页，自动定位到对应事件并短暂高亮。
- 通过顶部选项卡正常进入事件页时保留事件页上一次滚动位置；从主页卡片或圆形进入时，目标事件定位覆盖原滚动位置。

## 7. 全局操作区

- “全部暂停/全部恢复”和“全部重启”在主页和事件页保持相同位置。
- 事件页的“添加事件”位于同一操作区，并只在事件页显示。
- 全部暂停时长选择只在进入全部暂停后显示。
- 暂停时长选择位于“全部暂停/全部恢复”按钮左侧，并使用原本预留的空位；显示该设置时不得推动全局按钮改变位置。
- 选择具体暂停时长时，暂停剩余时间也在同一操作行显示；“直到手动恢复”不显示剩余时间。

## 8. 页面切换动画

### 8.1 主页与事件页

- 主页进入事件页时：
  - “添加事件”从右向左短距离移动并逐渐出现；
  - 事件列表作为一个整体从下向上拉入，覆盖主页圆形与事件卡片；
  - 共用的全部暂停/恢复和全部重启保持原位。
- 事件页返回主页时：
  - “添加事件”从左向右逐渐消失；
  - 事件列表整体从上向下离开；
  - 下方的主页圆形与最近事件卡片自然显露。

### 8.2 事件页与设置页

- 事件页进入设置页时：
  - 全部暂停/恢复、全部重启和添加事件从左向右逐渐消失；
  - 事件列表整体从上向下离开；
  - 前述内容接近消失时，设置页内容逐渐浮现，不停留在明显空白页面。
- 设置页进入事件页时执行反向过程：设置内容先淡出，三个操作按钮从右向左出现，事件列表从下向上拉入。

### 8.3 其他页面之间

- 主页和设置页等非事件页之间使用更短、更朴素的整体淡出与淡入。
- 普通页面淡入淡出建议控制在约 150–180 毫秒，事件页专属切换建议约 220–280 毫秒。
- 动画期间连续点击多个页面时，不排队播放全部完整动画；以用户最后选择的页面为目标，取消或接续当前动画。
- 事件列表只整体移动，不为每张事件卡片分别启动页面切换动画。
- 页面切换期间最多临时保留进入页和离开页的可见层；切换结束后停止非活动页面的可视刷新和动画。

## 9. 最近事件变化动画

- 在主页执行全部暂停或全部恢复后，如果最近三个事件的集合、顺序或内容发生变化，不能直接无过渡替换。
- 发生变化的卡片可以短暂弹动并闪过强调色，在动画的视觉峰值附近替换名称和倒计时。
- 圆形当前目标发生变化时，圆形短暂轻微膨胀，并在膨胀过程的视觉峰值附近替换名称、倒计时和圆环数据。
- “闪一下”使用克制的主题强调色，不使用大面积纯白闪烁或持续闪烁。
- 这些动画只在内容实际变化时运行；未变化的卡片不重复动画。
- 主页更新只比较逻辑层事件快照映射：
  1. 保存旧的最近事件 ID 和圆形当前事件 ID；
  2. 执行全部暂停、全部恢复或其他业务操作；
  3. 从最新事件快照重新计算最近候选；
  4. 按事件 ID 比较新旧结果；
  5. 只对新增、移除、换位或内容变化的槽位执行动画；
  6. 当前圆形目标仍有效时保留该事件，失效时回到新的第一候选。
- 卡片数量不变时，固定槽位不移动，在轻微缩放和强调色动画顶点替换内容；卡片数量发生变化时，卡片组短暂淡出并切换到对应的一、二、三卡片固定布局后淡入。

## 10. 软件渲染可行性复核

### 10.1 结论

- 已确认的主页构图能够支持 WPF 软件渲染，不需要因为增加“软件渲染（兼容模式）”而取消大型圆形、时间圆环、最近事件卡片或页面切换。
- 主页全部核心图形均属于 WPF 标准二维绘制、文字和短时变换范围，不依赖必须由独立显卡完成的三维场景、视频渲染或持续像素特效。
- 软件渲染的主要风险是窗口可见时的 CPU 和功耗，而不是功能无法实现；需要通过下一阶段的实际主页对照测量决定是否继续优化视觉实现。

### 10.2 当前设计中有利于软件渲染的条件

- 圆形和右侧卡片位置固定，普通动画不逐帧改变布局结构。
- 右侧最多只有三张卡片，不创建大量同时变化的可见元素。
- 圆环没有完整背景轨道，分量为零时不绘制对应弧线。
- 秒环只在每秒变化时短暂过渡，分、时、天环只在各自分量变化时更新。
- 页面隐藏或离开主页后停止主页逐秒视觉刷新和动画。
- 页面切换、卡片强调和圆形膨胀均为按需短时动画，不持续漂浮或循环播放。

### 10.3 软件渲染实现约束

- 圆环应使用局部、轻量的绘制组件，只使实际变化的弧线失效并重绘，不因为秒环变化重新布局整个主页。
- 位移、缩放和淡入淡出继续优先使用 `RenderTransform` 与透明度，不逐帧动画宽度、高度或边距。
- 避免在圆形或大面积卡片区域使用持续变化的模糊、复杂透明蒙版和高成本动态阴影；漂浮层次优先通过边框、底色和静态轻量效果表达。
- 目标事件切换时只更新圆形、圆环和对应卡片，不刷新无关事件卡片或事件页。
- 动画完成、中断、页面切走或窗口隐藏后，必须清理动画时钟、渲染回调和事件订阅。

### 10.4 本阶段测量

- 在“软件渲染（兼容模式）”和“硬件优先渲染”下分别测量：
  - 主页可见且无交互时；
  - 秒环逐秒变化时；
  - 卡片悬停切换目标时；
  - 主页与事件页、设置页切换时；
  - 窗口隐藏并停止界面刷新后。
- 每个场景至少记录 CPU、工作集、私有内存和托管堆，并复核 60Hz 与本机 120Hz 显示环境下的动画体验。
- 如果软件渲染未达到项目资源目标，先优化重绘范围、缓存和高成本视觉效果；是否减少已经确认的动画表现需要另行讨论。
- 2026-07-28 已在当前无独立显卡设备上完成 Release 完整应用初测，详细记录见 `docs/versions/NEXT_STAGE_HOME_NAVIGATION_VALIDATION.md`。
- 当前设备上的初测结论：
  - 软件渲染下主页可见稳定工作集约 `176 MB`、私有内存约 `93.5 MB`，稳定 CPU 通常为 `0–0.14%`；
  - 软件渲染下窗口隐藏后的工作集约 `24 MB`，稳定 CPU 通常为 `0–0.07%`；
  - 硬件优先渲染在当前设备上仍出现约 `1.09 GB` 工作集和约 `1.01 GB` 私有内存，属于需要保留兼容模式的实际设备差异；
  - 当前可见工作集比 `160 MB` 理想目标约高 `16 MB`，后续仍需优化；后台工作集和稳定 CPU 已满足当前弹性目标。
- 用户在普通交互桌面的复测确认：软件渲染内存已经降低到预期附近并可接受，但页面交互会明显变卡；硬件优先模式仍超过 `1 GB`，暂不针对可能的驱动原因进行专门修复，后续计划换其他电脑复测。
- 两种模式在发生页面交互时 CPU 都会短时明显升高；用户对比 QQ、微信后接受这一类交互峰值，空闲和后台占用仍按既有目标继续控制。

## 11. 待确认事项

1. 一、二、三张卡片布局的最终纵向间距、卡片宽高和相对圆形的精确坐标。
2. 圆形及圆环的最终直径、粗细和环间距，以及不同窗口宽度下的响应式缩放范围。
3. 深色主题中的最终亮度修正值，以及实际界面渲染后是否需要微调已确认色值。
